## 2. 对最近更改的评估

**方向正确、实测有效，但两处都只修了「一条路径」，同款风险仍在其余路径上。**

1. `max_tokens` 截断（bb3944a）：客户端传来超过部署 `max_output_tokens` 的值时，
   截断到上限而不是原样透传被上游 400——这是对的。**但只改了
   `OpenAICompatibleAdapter`**；Anthropic / Gemini / Ollama 三个适配器的
   `build_payload` 仍原样透传。同一个漏洞修了 1/4。
2. SSE 注释行白名单（bb3944a + 次日上午补丁）：对不认 SSE 注释行的客户端不发
   `: ping`，避免断连——方向对；上午把新版 OpenAI SDK 的 UA（`openai/python`、
   `openai/js`）补进白名单也是对的。**但白名单是硬编码**：客户端生态一变就要改
   代码、发版、重启，运营者没有自助入口。

## 3. 四类缺陷与修复（全部已实现 + 回归测试）

### A. 出站参数治理没有单一事实源

- **根因**：截断逻辑写在某一个适配器里，而不是所有适配器共用的基类。
  「客户端参数到上游 payload」的治理规则天然属于基类职责。
- **修复**：`ProviderAdapter._clamped_max_tokens(request, deployment)`——
  `None`/`<=0` 返回 `None`（交给部署默认值），超过 `deployment.max_output_tokens`
  截断并记 info 日志。四个适配器统一
  `self._clamped_max_tokens(...) or deployment.max_output_tokens`。
- **回归**：`tests/test_adapters.py::TestMaxTokensClamping` 补 4 例
  （Anthropic/Gemini/Ollama 超限截断 + Anthropic 零值回落）。
- **不变量**：今后新增适配器自动继承保护；谁绕开基类自己写截断，测试会抓住行为漂移。

### B. 热加载不完整（本次审查的核心发现）

- **现象**：改 `config.yaml` 后日志与 `/health` 都显示「已自动 reload N 次」，
  但 `request:` / `retry:` / `admin:` / `deploy:` / `credential_rotation:` 段
  **静默不生效**。AGENTS.md 曾把其中两段记成「必须重启」的坑（2026-10-26、
  2026-11-16 两条实测）——那是把症状当成了规格。
- **根因**（三处各自独立）：
  1. `reload_config()` 拿到 `load_app_config()` 返回的**新 Settings 对象**，
     却从不写回 `container.settings`——所有持有旧引用的服务永远看启动快照；
  2. `Scheduler.policy` 只在 `__init__` 设一次，reload 不重建；
  3. `CredentialPool` 的轮换策略只在建池时读一次。
- **第一性原理判断**：热加载的承诺是「改完 YAML 自动生效」。正确的规格不是
  「哪些段碰巧能热更」，而是**每个字段都必须被明确分类**：能热更的原地热更，
  不能热更的（构造期捕获：监听端口、DB 连接、并发闸等）**点名报告需要重启**，
  绝不假装生效。
- **修复**：
  - `settings.py` 新增 `RUNTIME_RELOADABLE_FIELDS` / `STARTUP_ONLY_FIELDS`
    两个 frozenset，覆盖全部字段（守卫测试钉住：不相交、并集=全集，
    新字段不分类就红）。启动期 15 个：version/environment/host/port/log_level/
    log_json/config_dir/data_dir/database_url/db_echo/max_request_body_mb/
    watch_config/watch_config_interval/agent_max_concurrent/agent_max_children_total。
  - `container.reload_config()` 调 `_apply_runtime_settings()`：把可热更字段
    **原地 setattr 到同一个 Settings 对象**（不换引用，持有者一起看到新值），
    并重建 `scheduler.policy` 与四个调度旋钮、`request_service.trim_history_tokens`、
    `pool.set_rotation()`（新方法）。
  - 启动期字段改了**不应用**，进 `container.pending_restart_fields`；
    reload 返回值新增 `settings_applied` / `restart_required`，
    `/health` 的 `config` 块暴露 `restart_required`。
  - 控制台「需要处理」面板新增 restart 行（一键重启），reload toast 提示
    「另有 N 项设置需重启才生效」。顺带修了无 fix 行渲染 `undefined` 按钮的小 bug。
- **回归**：`tests/test_config_watch.py` 补 4 例——retry 段到达调度器、
  request 段原地热更（断言 `container.settings is live`）、rotation 段到达凭据池、
  启动期字段只报告不应用。
- **测试基建坑（已修）**：容器级测试会被真实 `.env` 污染——`load_app_config`
  每次调 `load_dotenv_file()` 把运营者的 `ZKAI_*` 灌进 `os.environ`，按
  「环境变量优先于 YAML」的产品契约盖掉测试写的 YAML。新增
  `no_operator_dotenv` fixture（置空加载器 + 清相关变量）挡掉。

### C. 死配置键：示例声明了、代码不消费

- **发现**：`config.example.yaml` 里 `deploy.burner_dir`、顶层 `watch_config` /
  `watch_config_interval` 有注释教运营者改，但 `_SETTINGS_SECTIONS` 桥接表没登记
  ——改了静默无效。另 `request.max_input_tokens` / `max_request_seconds` 只有
  环境变量入口，YAML 写了不认。
- **修复**：`loader.py` 补 6 条桥接（顶层标量键用 `section=""` 新支持）；
  新增 `RAW_CONSUMED_SECTIONS`（cooldown/retry/agent_auto/credential_rotation/
  events 这些整段被服务直接消费的段）。
- **守卫工具化**（把「别犯第二次」变成测试）：
  - `test_every_example_config_key_is_consumed`：逐键核对 config.example.yaml
    的每个键都有消费方（桥接表或整段消费名单），新键不登记就红；
  - `test_every_settings_field_is_classified_for_reload`：见 B。
- **回归**：`tests/test_config.py` 补 4 例（死键桥接、request 两守卫桥接、
  字段分类完备、示例键全消费）。

### D. SSE 白名单从硬编码变成「内置 + 配置追加」

- **修复**：`Settings.sse_comment_user_agents`（逗号/空白分隔的追加名单，
  可热更）；`chat.py` 新增 `extra_sse_ua_keywords()`，贯穿 chat / messages /
  responses 三条流式路径（`keepalive_interval` 与 `wants_sse_comments` 都加
  `extra_keywords` 参数）。**内置名单永远生效**，配置只做追加——运营者可以
  放行新客户端，但不能误关对已知不合规客户端的保护。
- **回归**：`tests/test_api.py` 补 2 例（配置追加生效；配置了 UA 的客户端
  收到 `zkai_meta` 且收不到 `: ping`）。
- **示例同步**：`config.example.yaml` 的 request 段补
  `sse_comment_user_agents` / `max_input_tokens` / `max_request_seconds` 及中文注释；
  retry 段注释改为「随 reload 热生效（2026-11-19 起）」。

## 6. 刻意不做与后续建议

**刻意不做**（避免过度工程）：

- `scripts/check_config.py` 不加 restart-pending 检查：那是**运行时状态**，
  不是静态自洽问题；`/health` + 控制台已经可见，再进静态体检是职责混淆。
- 不把 `STARTUP_ONLY_FIELDS` 里的字段强行热更：监听端口、DB 连接、并发闸
  在构造期被捕获，假装热更会制造「改了没生效」的新谎言。点名重启是诚实的规格。
- 不内置「从 UA 猜客户端能力」的模糊匹配：白名单是精确子串匹配，宁可运营者
  显式追加，不做不可解释的启发式。

**后续建议**（按价值排序，未实施）：

1. **AGENTS.md 拆分预警**：余量仅 2,263 字节。下次沉淀前，把「入站断连」或
   「外部 CLI 执行体」节的过程性内容拆去 docs/，结论留原处。
2. **服务器核对**：`retry.max_credentials_per_deployment` 本机 3、服务器曾遗留 9
   （AGENTS.md 旧坑）。热加载修好后，改服务器 YAML 即可生效，但**首次仍建议
   核对现役值**；服务器上「deploy:/retry: 段必须重启」的旧运维记忆可以更新为
   「热更 + 看 restart_required」。
3. **流式路径结构一致性守卫**：三条路径（chat/messages/responses）靠人记同步，
   本次 UA 追加参数就改了三处。可考虑抽公共流式骨架或加结构守卫测试，
   属新工作，不在本次范围。
