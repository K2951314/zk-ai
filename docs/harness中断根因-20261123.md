# harness 中断：心跳白名单与预取窗口（2026-11-23）

> 一次性排查留档。结论已上提：`AGENTS.md`「入站断连」节的
> 「2026-11-23：harness 第三个根因」。规则以 AGENTS.md 为准，本文只作证据与过程。

## 1. 起因

运营者反馈：同一网关下 Claude Code / Qoder 正常，DeepSeek harness 经常中断。
仓库里已有 `docs/harness中断根因-20261026.md`（结论：商汤 tpm 打爆），
但那份是 10 月的证据；11 月又改过流式（心跳、保底腿、Retry-After），
所以这次用**现役服务器**的数据重新核。

## 2. 取证（本机 DB 已无真实流量，全部来自服务器）

- 现役服务器：腾讯 `115.159.87.18`，`/opt/zkai`，HEAD `aa9309b`（2026-11-19），
  DB 在 `/var/lib/zkai/zkai.db`（只读打开）。
- **先纠正一个错误前提**：`undici` 不是 harness。UA/IP 对照：

  | UA | IP | 请求数 |
  |---|---|---|
  | `deepseek-harness/0.2.2-rc.5 (+https://github.com/deepseek-ai/deepseek-harness) dsh-profile/desktop` | 27.219.106.1 | 548 |
  | `undici` | 122.4.120.62 | 786（与 claude-cli 同机） |

  两个客户端的失败形状完全不同，混在一起会得出错误结论。

## 3. 根因一：心跳白名单的 UA 写错了

`app/api/chat.py` 的 `_PING_USER_AGENTS` 里写的是 `ds-harness`，线上发来的是
`deepseek-harness/...`。子串匹配验证（改造前）：

```
codex            -> False
ds-harness       -> False   ← 线上原文
deepseek-harness -> True
openai-python    -> False
```

即**这条「为 harness 加的心跳」从上线起对 harness 零生效**。
服务器 DB：618 条 harness 流式请求、529 条成功，全程没有一条 `: ping`。

顺带发现：`claude-cli/...`、`undici` 也不在名单里。所以「Claude 更稳」
不是因为它收到心跳，而是别的因素（它自己更耐静默/走的 messages 路径
首帧就发 `assembler.start()`）。

## 4. 根因二：预取窗口内零字节

`_stream_response` 为让预检错误返回真实 HTTP 状态码，先 `anext` 一次再建
`StreamingResponse`；调度器的换 Key / 换部署 / 退避重试**全在这个窗口里**，
期间一个字节都发不出去。

服务器实测 harness 首块延迟（11-21 起 504 条成功流式）：

| 分位 | 首块 | 整条流 |
|---|---|---|
| p50 | 8.65s | 11.8s |
| p90 | 30.2s | 40.0s |
| p95 | 49.4s | 70.7s |
| p99 | 141.5s | 149.2s |
| max | 461.0s | 461.1s |

首块 >60s 的 21/504（4.2%）、>120s 的 6/504。超 30s 的那批集中在
AMD/ds4.1（76 条，均 62.3s）与 sensenova/deepseek-flash（18 条，均 30.0s）。

## 5. 修法与真机验证

改动（三条流式路径结构一致）：

1. 白名单补 `deepseek-harness`（保留 `ds-harness` 别名）。
2. 新增 `request.stream_prefetch_timeout`（默认 10s，可热更）：
   超时**不取消**在飞 `anext`（跨心跳同一 task 的不变式不破），
   先返回 200 + 心跳，事件稍后照常到达。
3. 窗口外抛出的 `ZKAIError` / 任何异常，三条路径都转成**流内 error 事件**
   ——否则 Starlette 报 `Caught handled exception, but response already started`
   并把客户端唯一的错误信号吞掉。这一条是**自己引入后真机抓到的**。

真机验证（本机网关 + 一个静默 45s 的假上游，UA 用线上原文）：

```
status: 200 at 10.18 s          ← 预取窗口生效（改造前是 45s）
ping #1 at 20.19 s
ping #2 at 30.20 s
ping #3 at 40.21 s
content at 45.22 s -> 'OK'
[DONE] at 45.22 s
```

失败分支（假上游延迟后报错）：

```
status: 200 at 10.15s
ping ×3
ERROR at 40.48 -> AllAttemptsFailed(... upstream_error ...)
[DONE] at 40.49
网关日志 "response already started" 计数：0
```

真实上游回归（本机网关打商汤/AMD 真配额）：

```
zk-auto + harness UA   -> 200, first 0.81~1.1s, meta=1, content='2'
zk-auto + 工具调用请求 -> 200, saw=[tool_calls, arguments, DONE], 无 error
zk-auto + 长推理请求   -> 200, saw=[content, DONE]
```

（同一脚本在改 `stream_prefetch_timeout` 之前跑出 `text_len=0`，
是 `strip_reasoning` + 预取异常吞掉导致的，修复后恢复。）

## 6. 回归测试

三条流式路径各两条（结构必须一致，改一条就要改三条）：

| 断言 | chat | messages | responses |
|---|---|---|---|
| 心跳早于第一个内容块（响应体没被预取阻塞） | `test_slow_first_chunk_still_delivers_the_whole_answer` | `test_prefetch_window_starts_the_body_before_the_first_chunk` | `test_prefetch_window_starts_the_body_before_the_first_chunk` |
| 窗口外失败 → 流内 error 事件 | `test_failure_after_the_prefetch_window_becomes_an_error_event` | `test_failure_after_the_prefetch_window_is_an_error_event` | `test_failure_after_the_prefetch_window_is_an_error_event` |

其余三条：

- `tests/test_api.py::test_keepalive_reaches_the_real_deepseek_harness_user_agent`
  —— 用线上 UA 原文钉住名单。
- `tests/test_api.py::test_prefetch_window_keeps_real_status_codes`
  —— 窗口内到达的错误仍是真实 HTTP 状态码。
- `tests/test_config.py::test_stream_prefetch_timeout_is_bridged_from_yaml`
  —— 新键必须能从 YAML 改到。

**写这些测试的两个坑**（都会让测试变成「永远绿」的摆设）：

1. `tests/conftest.py` 的 `Behavior.delay` 只在**内容块之间**生效，第一个事件
   （`role` 块）永远零延迟——只用 `delay` 根本触发不到预取窗口。为此新增
   `Behavior.first_delay`（首字节前的静默秒数），并把失败分支挪到 sleep 之后。
2. 只断言 `status_code == 200` 没有鉴别力：旧写法（先 `anext` 再建响应）
   在慢上游下也照样 200。必须断言**心跳出现在第一个内容块之前**。
   messages 路径的开场是 `message_start`（Anthropic 语法要求），心跳只能排在
   它之后、`content_block_start` 之前。

变异验证：把 `app/api/chat.py` 换回改动前的版本，chat 两条断言双双失败
（一条无心跳、一条得到 503），恢复后 SHA256 与 stash 前一致。

## 7. 未修 / 刻意不做

- `strip_reasoning` 是全局开关：思考内容仍被统一丢弃。要做到「harness 看思考、
  别人不看」需要按请求开通道，属产品决策，本次没动。
- Claude Code / undici 仍不在心跳名单里。它们目前不依赖心跳；
  若出现静默断连，运营者可用 `request.sse_comment_user_agents` 追加，无需改代码。
