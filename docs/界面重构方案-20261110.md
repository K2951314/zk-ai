# 控制台界面重构方案（2026-11-10）

> 这份文档是**规划 + 已落地记录**。规划部分逐段可执行、可单独回滚；
> 每段做完后在这里更新状态，不另开新文档。
>
> 起因：运营者要「把界面结构重新规划，审视功能是否冗余，和业界对照」。
> 调查方式：6 个只读审计（内置视图 / 独立页 / Agent 任务台 / 前后端对应 /
> 测试契约 / 配置视图与弹窗）+ 2 个业界对照，**所有高严重度结论由主会话逐条
> 复核源码**，其中 2 条被证伪（见 §7）。

## 0. 结论先行

**问题不在「功能太多」，在「按操作开面板」而不是「按对象组织」。**

后端 91 个端点按领域拆得很干净（providers / models / stats / burner / agent /
events / chatgpt），真正的业务对象只有 **4 个**：模型与部署、凭据、请求与用量、
事件与任务。但前端摆了 **11 个一级入口 + 8 个弹窗 + 5 套前端**（console.js +
4 个独立页），同一个对象散落在多个入口里：

| 对象 | 现在的入口 | 冗余形态 |
|---|---|---|
| 模型 | 「模型与别名」「模型与价格」「模型市场」 | 3 个一级入口 + 3 份模型表 |
| Key | 「凭据池」+ 「加 Key」弹窗 + 「供应商」弹窗 + 「限额」弹窗 | 1 个页面 + 3 个弹窗 |
| 请求 | 「请求记录」「用量统计」「体检」 | 3 处各算一遍 |
| 事件/任务 | 「事件流」「Agent 任务台」「任务空间」 | 3 个 iframe，各一套基础设施 |

**重构方向**：一级导航收成 **4 个板块**（巡检 / 配置 / 观测 / 自动化），
按「这个功能属于哪个对象」归位；一年用一次的（模型市场、客户端接入、消耗器）
下沉为二级；删掉已经只剩跳转壳的 `/ui/report`。

### S1.3 移动端导航改为派生，不再手写三份

**发现的问题**：导航有三份各自维护的清单——`index.html` 的 `<nav>`、
`console.js` 的 `MNAV`（底栏）、`console.js` 的 `mnavMore()`（抽屉手写数组）。
加一个视图要改三处，漏一处就出现「桌面上有、手机上找不到」。
`docs/界面交互方案.md` §2.2 早就写了「不允许出现两份手工维护的导航文案」，
但这条规则一直没被执行。

**改法**：
- `MNAV` 保留（移动端需要人工挑选 3 个高频项），第三格从「消耗器」换成「凭据」——
  消耗器已停用，而凭据是排障时最常开的一页。
- `mnavMore()` 从 `#tabs` 的 DOM **派生**：取全部 `button[data-view]`，减去
  `MNAV` 里的三项。文案提取用 `cloneNode` 后摘掉 `.ico` / `.nav-off`——
  不能直接用 `lastChild.textContent`，消耗器那个按钮的最后一个子节点正好是徽标。

### S4：Agent 任务台与「任务空间」的心智模型合并 —— ✅ 已按「会话是主角」落地

**决策（我替运营者定的，理由）：会话是主角，任务空间是它的属性。**

后端 `service._enter_task_space` 用 `session_id` 建空间，两者**一对一绑定**。
但界面上它们是两套平级导航：左边会话列表，另一个一级入口是任务空间卡片，
用户得自己猜哪张卡属于哪个会话。Agent 类产品的共识是「会话是唯一主角，
其他都是属性」（见 §6.2），所以不做成平级的第二个主角。

**改法（最小侵入，不动后端）**：
- `loadSessions()` 同时拉 `/zkadmin/agent/sessions` 和 `/zkadmin/agent/taskspaces`，
  按 `session_id` 建索引存进 `state.spaceBySession`。
- 会话列表里，有空间的会话显示一个 `📁` 标记（`title` 里有 task_id）。
- 选这个做法而不是改 `list_sessions` 返回 `task_id`，是因为**另一个对话正在改
  后端**，而前端聚合不需要动任何 Python 文件——零冲突面。

**没做**（留待将来）：把「任务空间」从一级导航降成会话里的详情面板。
那是一步更大的改动（要动 `taskspaces.html` 的定位与 `data-view`），
且当前标记方案已经解决了「看不出绑定关系」这个真问题。

**硬约束**（`tests/test_console_zh.py`）：
- `var ZKUI` 必须存在（`test_ui_pages.py` 断言）
- `promptLogin` 必须存在
- 每个 `<script>` 块必须有顶层声明
- 顶层声明不许重复（重复 = 整段脚本中止，页面静默失效）

## 4. 与另一个对话的并发约束（重要）

改的时候另一路 Claude 也在同一工作目录里。已确认的隔离边界：

| 对方改的 | 我改的 | 冲突面 |
|---|---|---|
| `app/api/admin/providers.py`<br>`app/credentials/*.py`<br>`app/retry/classifier.py`<br>`app/routing/scheduler.py`<br>`tests/test_quota_reset.py` | `app/web/*`<br>`app/api/ui.py`<br>`docs/界面*.md`<br>`README.md`<br>`tests/test_console*.py`<br>`tests/test_api.py` | **无文件重叠** |

**纪律**：
1. 只动自己集合内的文件；对方集合内的文件一律不碰。
2. 每段做完立刻跑全量门禁 + 真机验证，让磁盘上始终是一个「能跑」的版本。

## 6. 业界对照：值得学与不该学

**这次 2 个业界对照 agent 因额度问题失败**（`no_available_credential: 供应商 AMD`），
只能用我自己的知识给判断。以下**标注为推断，未联网核实**：

### 6.1 网关控制台类（LiteLLM / one-api / OpenRouter / Portkey / Cloudflare AI Gateway）

| 做法 | 本项目 | 判断 |
|---|---|---|
| 一级导航按「Key / 模型 / 日志 / 用量 / 设置」分 | 改成「巡检 / 配置 / 观测 / 自动化」 | ✅ 更贴合单人运维：先问「现在好不好」，再问「哪里出问题」 |
| 首页是**健康总览 + 待处理**，不是 KPI 堆 | 总览已有「需要处理」面板 | ✅ 已是这个方向，保留 |
| 请求日志是**一级入口**且能按错误类型筛 | 「观测」组里，需点两下 | 可接受（单人使用频次中等） |
| 模型/路由配置单独一页、表单用弹窗 | 「模型」页 + 3 个弹窗 | ✅ 一致 |
| **多租户 / 团队 / 账单 / SSO** | 没有，也不需要 | ❌ 不学。这是 SaaS 包袱，单机单人用不上 |

### 6.2 Agent 任务台类（Claude Code / Codex / Devin / OpenHands / Manus）

⚠ 全部为推断，未核实：

| 做法 | 本项目 | 判断 |
|---|---|---|
| 主界面是**对话流**（不是任务列表 / 看板） | 已是这样 | ✅ |
| 左侧**会话列表**、可切回历史 | 已有 | ✅ |
| 审批呈现为**行内卡片**（阻塞在 transcript 里），不是弹窗打断 | 已有 | ✅ |
| **任务空间/工作区**是会话的属性，不是独立页面 | 现在是独立页 | ⚠ S4 要解决 |
| 历史按时间轴 / 分支组织 | 只有平铺列表 | 单人用够，不急 |
| 后台任务手机可批 | 飞书卡片 → 控制台 | ✅ |

**Takeaway（推断）**：Agent 类产品的共识是「**会话是唯一主角，其他都是它的属性**」。
本项目的「任务空间」被做成了平级的第二个主角，这是 S4 要解决的核心。

## 7. 审计结论的复核记录（两条被证伪）

审计读手提交了 3 条「高严重度」结论，逐条对着源码验证：

| 结论 | 核实结果 | 证据 |
|---|---|---|
| 「启用/禁用 Key 会打不存在的路由 `/zkadmin/credentials/{id}/enable`」 | ❌ **证伪** | 后端 `app/api/admin/providers.py:1031/1050` 就定义为 `@router.post("/credentials/{credential_id}/enable")`，挂在 `/zkadmin` 前缀下 → 实际路径正确 |
| 「`models.html` 的 `api()` 无条件设 `Content-Type: application/json`，Chrome 会报 fetch TypeError」 | ❌ **证伪** | `models.html:122` 走的是 `ZKUI.api`，`common.js:43` 只在 `opts.body` 存在时才加 Content-Type |
| 「`DEP_PRESERVE` 缺 `reasoning_efforts`，控制台一保存就抹掉档位证据」 | ❌ **证伪** | `console.js:1667-1675`：`efforts` 从隐藏 input `[data-df="reasoning_efforts"]` 直接读，`next.reasoning_efforts` 恒为已定义值，`DEP_PRESERVE` 的 `prev[k] !== undefined && next[k] === undefined` 分支走不到 |
| 「`scripts/smoke_test.py` 打 `/admin/*` 必 404」 | ✅ **成立** | `main.py` 只 `include_router(admin.router)`（prefix=`/zkadmin`），全仓无 `/admin` 别名；smoke_test 却用 `BASE + /admin/credentials` |
| 「`events.html` 的主题不跟随控制台」 | ✅ **成立** | events 用 `@media (prefers-color-scheme)`，控制台用 `dataset.theme`，iframe 子文档不继承 |
| 「导航三份清单各自维护」 | ✅ **成立** | `index.html` `<nav>` + `MNAV` + `mnavMore()` 手写数组 |

**教训（写进 §4）**：读手会把「看起来像 bug」的代码模式当结论报上来，尤其
**跨文件的路径拼接**（`api()` 的 `/admin→/zkadmin` 改写）最容易误判。
高严重度结论必须对着源码复核，不能直接进工单。

## 8. 不做什么

| 不做 | 理由 |
|---|---|
| 引入前端框架（Vue/React） | 违背单文件零依赖约定，收益低 |
| 拆构建工具链 | 「双击 start_gateway.cmd 就能用」是产品前提 |
| 合并 4 个独立页为单页 | iframe 隔离能让 Agent 正在跑的会话在切视图时不重置（`embedFrame` 只建一次） |
| 删掉消耗器 UI | 它在磁盘上、配置里都还在；灰显比消失更好恢复 |
| 多租户 / 登录体系 / 权限模型 | 单人自用，没有第二个用户 |
