# 1. 界面结构

## 1.1 信息架构（层级 ≤ 2）

```
ZK-AI 控制台
├─ 总览            （巡检首屏 · 默认视图）
├─ 凭据池          （Key 管理）
│   ├─ 加 Key / 供应商 / 限额 —— 以弹窗承载，不新增页面
├─ 请求记录        （日志 + 详情抽屉）
├─ 用量统计        （成本与 Token 分析）
├─ 体检            （配置一致性 · 实时态 + 历史报告）
├─ 模型与别名      （模型 · 别名 · 模型市场导入）
└─ 积分消耗器      （账号账 · 实时日志 · 高级配置）
辅助层（非视图，覆盖在当前视图之上）
├─ 管理令牌登录    （全屏遮罩）
├─ 客户端接入      （弹窗：base_url / 令牌 / 配置片段）
├─ 主题切换        （顶栏按钮，浅/深）
└─ 自动刷新        （顶栏下拉：关 / 5s / 10s / 30s）
```

规则：**每个功能只归一层**。表单类操作一律用弹窗或抽屉，不跳转、不换页，关闭后回到原视图原滚动位。

## 1.2 页面清单

| # | 视图 | 视图 ID | 核心对象 | 承载弹窗 | 承载抽屉 |
|---|---|---|---|---|---|
| 1 | 总览 | `overview` | KPI、需处理、供应商、最近请求 | — | 请求详情 |
| 2 | 凭据池 | `pool` | Key 表、冷却倒计时 | 加 Key、供应商、限额 | — |
| 3 | 请求记录 | `requests` | 筛选、日志表、分页 | — | 请求详情 |
| 4 | 用量统计 | `usage` | KPI、按天/别名/供应商/模型/凭据 | — | — |
| 5 | 体检 | `report` | 此刻在跑、告警、历史报告 | — | — |
| 6 | 模型与别名 | `models` | 模型表、别名表 | 模型编辑、别名编辑、模型市场 | — |
| 7 | 积分消耗器 | `burner` | 窗口 KPI、账号账、实时日志、高级配置 | — | — |

辅助：`#auth`（令牌登录）、`#chatgpt-modal`（客户端接入）。`/ui/agent`、`/ui/report` 为独立页面，从移动「更多」抽屉入口进，不并入本控制台导航。

## 1.3 布局模式（全站统一骨架）

```
┌────────────────────────────────────────────────────────┐
│ 侧栏 240px  │            顶栏 56px                      │
│ ┌────────┐  │ 连接状态 · 隔离告警条 · 自动刷新 · 主题…   │
│ │品牌区   │  ├────────────────────────────────────────────┤
│ │ 56px   │  │                                            │
│ ├────────┤  │            内容区（滚动）                   │
│ │导航    │  │  view-head（标题 + 一句话说明）              │
│ │ 分组   │  │  toolbar / filters（操作条）                │
│ │        │  │  内容块…（KPI 网格 / 卡片网格 / 表格 / 节）  │
│ │        │  │                                            │
│ ├────────┤  │                                            │
│ │版本/运行│  │                                            │
│ └────────┘  │                                            │
└────────────────────────────────────────────────────────┘
```

- **左侧栏固定，内容区独立滚动**；顶栏固定在内容区顶部，不随内容滚。
- 每个视图内部纵向顺序固定为：**view-head → 操作条 → 全局告警（如有）→ 数据块**。
- 数据块间距 24px（桌面）/ 16px（移动）；表格与卡片都放进统一容器（`tablewrap` / `card`），宽度 100%。
- 页面最大宽度 1600px，超宽屏居中，两侧留白对称（控制台要宽度，不按官网 1120px 封顶）。

# 2. 导航逻辑

## 2.1 桌面侧栏（≥ 1024px）

```
ZK-AI 本地 AI 网关控制台     ← 品牌区，点击回「总览」
─────────────────────────
监控
  📊 总览
  🔑 凭据池
  📨 请求记录
  📈 用量统计
  🩺 体检
配置
  🧩 模型与别名
  🔥 积分消耗器
─────────────────────────
版本 x.y.z · 已运行 3d 2h    ← 侧栏脚注，只读
```

- 分组标题（监控 / 配置）为 11px 中性文字，不可点击。
- 导航项高度 36px，圆角 6px，选中态：accent 浅底 + accent 深字 + 左侧 2px accent 竖条。
- 切换视图 = **单页切换**（显示/隐藏 `section.view`），不整页刷新、不改 URL query 之外的东西；视图切换后内容区 `scrollTop = 0`。
- 侧栏宽度 240px 固定，不折叠（本产品导航项少，折叠收益为零、认知成本为正）。

## 2.2 移动底栏（< 1024px）

```
┌──────────────────────────────────────┐
│                内容区                  │
├──────────────────────────────────────┤
│  📊总览   🧩模型   🔥消耗器   •••更多  │  ← 底栏 56px + safe-area
└──────────────────────────────────────┘
```

- 底栏 4 项等分，每项触控热区 ≥ 56×56px（含 safe-area 前有效高 ≥ 48px）。
- 「更多」打开**底部抽屉**（非全屏），列出：凭据池、请求记录、用量统计、体检、Agent 任务台，每行 48px 高。
- 选中项：icon + 文字变 accent 色 + 顶部 2px accent 指示条。
- 底栏与抽屉 DOM 由桌面导航派生（同一份清单），**不允许出现两份手工维护的导航文案**。

## 2.3 切换与返回策略

| 行为 | 规则 |
|---|---|
| 视图切换 | 立即切 DOM 显示，数据按该视图 `load*()` 拉一次；自动刷新计时器全局共用一个，不随视图重建 |
| 弹窗打开 | 记录来源视图与触发元素；关闭后焦点回到触发元素 |
| 抽屉打开 | 同上；抽屉打开时底栏/侧栏不失效，Esc 可关 |
| 浏览器返回 | **默认不劫持**。弹窗/抽屉不进 history；若未来加了深链（如 `#requests`），返回 = 回总览 |
| 二次进入视图 | 保留筛选与分页状态（如请求记录的 filters 已有 `keepFilters` 行为，全站保持该原则） |
| 跨视图跳转 | 「需处理」面板的修复按钮跳到对应视图并**自动打开对应弹窗**（如「加 Key」直接开加 Key 弹窗） |

# 3. 主要操作流程

场景 A–G。每条流给正常步骤 + 异常分支。所有异步动作遵守第 4 节状态规则。

## A. 每日巡检（目标 30 秒内判断「系统是否正常」）

```
打开控制台
 → 看顶栏连接点（绿=healthy / 红=不可达）+ 状态行一句话
 → 若有隔离告警条（amber）→ 读隔离了几个、还剩多久
 → 总览首屏：KPI 2 枚（可用凭据 x/y · 60 分钟失败率）
 → 「需要处理」面板：0 条 = 正常收工；有条目 → 走 B/E/F 对应流程
 → 供应商卡片扫一眼状态点 → 滚到「最近请求」看有没有连续红
```

异常分支：
- 连接点红 → 状态行必须写清是「网关连不上」还是「未登录」，两者文案不同（见 4.5）。
- 失败率 > 20% → KPI 自动转 `err` 色，配文字「失败率偏高」，不靠颜色单独表意。
- 「需要处理」每行必须带一个**一键跳转动作**（加 Key / 导入模型 / 复制修复命令 / 清冷却），不允许只给一句提示。

## B. 凭据池 · Key 管理

```
凭据池 → 表格扫状态/冷却倒计时
 → 加 Key：「➕ 加 Key」→ 选供应商 → 填 ID/环境变量名 → 保存 → Toast
 → 调权重：行内「优先级」直接改数字 → 失焦即保存 → Toast
 → 冷却：行内倒计时；「🧹 全部清冷却」需二次确认
 → 启/停单把 Key：行内开关 → 立即生效 → Toast
 → 限额：「⚙ 限额」→ 按供应商加规则 → 「保存生效」
```

异常分支：
- 没有可加 Key 的供应商 → Toast 报错并提示「先在供应商里配好」+ 跳供应商弹窗按钮。
- 限额规则没填任何上限 → 阻止保存，字段级错误提示「至少设一个上限」。
- 保存失败（网络/后端）→ 错误 Toast + 表单值不丢失，按钮恢复可点。
- 删除类操作（删除 Key、删除供应商）→ 确认弹窗写清后果（「该供应商下 N 把 Key 一并删除」）。

## C. 模型路由 · 配别名 / 导入市场

```
模型与别名
 → 「🧺 模型市场」→ 选供应商 → 探测可用模型 → 勾选 → 导入 → Toast
 → 别名区「➕ 新建别名」→ 填名称/策略/目标链（有序）/接口模型
 → 校验：接口模型必须在目标链内，否则字段报错
 → 保存 → 「🔍 验证可调用」→ 结果 pill（可调用 x/y）
```

异常分支：
- 供应商没有任何可用 Key → 模型市场入口直接 Toast 提示，不进空壳弹窗。
- 探测返回空 → 列表区显示空态「这个供应商没有可列的模型」，保留「手动添加模型」路径。
- 验证有不可用模型 → 结果行红色 pill + 错误类型中文 + 「查看详情」进请求记录并带上该模型筛选。

## D. 用量分析

```
用量统计 → 选时间窗口（1/7/30 天）→ KPI（请求数/入/出/成本）
 → 按天看趋势 → 按别名/供应商/模型/凭据交叉看
 → 发现异常（某别名成本暴涨）→ 点行 → 跳请求记录并预填筛选
 → 「🧮 回填历史成本」→ 确认弹窗 → 结果 Toast
```

异常分支：
- 窗口内无数据 → 每张表各自空态，KPI 显示 `-`，不显示 0（避免误读）。
- 回填无待补记录 → Toast「没有需要回填的记录」，不报错色。

## E. 故障排查

```
看到告警 / 失败率高
 → 总览「▶ 立即健康检查」→ 按钮转 loading → 结果表（凭据/结果/延迟/错误）
 → 仍不明 → 请求记录 → 筛选 status=error → 点行开详情抽屉
 → 抽屉看：路由落点、尝试明细、每次上游错误原文（中文展示，原文在 title）
 → 配置层问题 → 「🩺 体检」→「此刻在跑」+ 历史报告 → 按报告建议修
 → 隔离部署 → 顶栏告警条看剩余时间；修好后任意一次成功自动恢复（文案写明）
```

异常分支：
- 健康检查超时 → 结果区显示「检查未完成」+ 错误，不空白。
- 请求详情 `attempts` 为空（历史流式请求）→ 明确写「无尝试记录（可能是修复前的流式请求）」，不显示空表。
- `/health` 可达但 `/admin/*` 401 → 视图内显示登录提示卡，不伪装成「无数据」。

## F. 积分烧录

```
积分消耗器
 → 首屏 KPI：5h 剩余 / 本周剩余 / 最高风险账号 / 单条成本 / 费率 / 安全系数
 → 每账号窗口账：看状态（活跃/停靠/限流停靠/已救济）
 → 校准：改 left_5h / left_week → 行内实时换算「≈N 条」
 → 「预演改动」→ 显示 diff → 「保存改动并重启消耗器」→ 确认弹窗 → Toast
 → 启停进程：启停按钮 → 状态 pill 更新
 → 实时日志：跟随/暂停/复制/清屏
```

异常分支：
- 某账号填 0 = 停止该账号，确认弹窗**单独点名账号**，文案「这会把 X 移出烧录队列」。
- 保存失败且后端给了 `command` → Toast 下方给**可复制命令**（不用 4 秒就消失的 toast 承载命令，用就地展开块）。
- 账本过期（`ledgerStale`）→ KPI 副文案加 ⚠ 与账龄，不阻塞操作。
- 消耗器进程未运行 → 页头 attention 条 + 启停按钮转「▶ 启动」。

## G. 客户端配置

```
顶栏「🌏 客户端接入」→ 弹窗
 → 展示 base_url、管理/客户端令牌、「复制」按钮
 → 选择目标客户端（Claude Code 等）→ 展示对应配置片段
 → 「写入本机 config.toml」（同机部署时）；不同机 → 只给片段 + 复制
```

异常分支：
- 未登录（无令牌）→ 按钮点击先开登录弹窗，回来后自动接着开客户端接入。
- 浏览器禁剪贴板 → 弹出只读文本域供手动全选，Toast 说明原因。
- 写本机失败（网关在远端）→ Toast 说明「请在自己电脑上按片段配置」，片段保持可见。

# 4. 状态反馈

## 4.1 状态清单

| 状态 | 触发 | 呈现 | 位置 |
|---|---|---|---|
| **loading** | 任一数据拉取中 | 首次进入：骨架块（灰底 3 行 ×2 列）；再次刷新：内容保留 + 顶部 2px 进度条 | 内容区顶部 / 块内 |
| **empty** | 列表/表格 0 行 | 表格空行合并单元格 + 一句话 +（可选）行动按钮 | 表格体内 |
| **error** | 请求失败 / 校验失败 | Toast（err）+ 行内错误（表单）+ 块级错误卡（含重试按钮） | 就近 + Toast |
| **success** | 写操作成功 | Toast（ok，2.5s 自动消失）+ 数据区立即重拉 | 右上 Toast 栈 |
| **offline** | `/health` 不可达 | 顶栏连接点红 + 状态行「网关连不上（原因）」+ 内容区顶部常驻横幅 | 顶栏 + 横幅 |
| **stale** | 数据超龄（自动刷新关闭且距上次 > 5min） | 内容区顶部灰条「数据更新于 X 分钟前 · 立即刷新」 | 内容区顶部 |
| **partial** | 部分子请求失败（如 usage 部分表空） | 仅失败块显示错误卡，其余块照常 | 块级 |

## 4.2 loading 细则

- 按钮级：点击后 `disabled` + 文案前加 `⏳`，**完成后必须恢复**（`finally`）。
- 超过 800ms 才显示 loading UI，避免闪烁；纯本地操作（筛选输入）不加 loading。
- 自动刷新进行中：顶栏「自动刷新」旁小转圈，**不整页闪**、不重置滚动位、不打断正在输入的表单。

## 4.3 empty 细则

| 场景 | 空态文案 | 行动 |
|---|---|---|
| 无凭据 | 「暂无凭据」 | 「➕ 加 Key」按钮 |
| 无请求记录 | 「无匹配记录」 | 「重置筛选」按钮 |
| 无用量 | 「该窗口内暂无数据」 | — |
| 模型市场空 | 「这个供应商没有可列的模型」 | 「手动添加模型」 |
| 消耗器无数据 | 「暂无数据（消耗器可能还没跑过）」 | 「▶ 启动消耗器」 |

空态**不使用插画**（控制台密度优先），用 12px 中性文字 + 可选按钮。

## 4.4 error / success 细则

- Toast 三档：`ok`（绿）、`err`（红）、默认（中性）。宽度上限 360px，同屏最多 3 条，多出的排队。
- **命令类信息不放 Toast**：凡带 `command` 的失败，就地展开可复制块（现有「需处理」的 envgap 行为推广到全站）。
- 表单错误：字段下方 12px 红字 + 输入框红边 + `aria-invalid`；保存失败不清空表单。
- 破坏性操作（删除 Key/模型/别名/供应商、停账号、清全部冷却、保存并重启消耗器）：**确认弹窗**，主按钮为 danger 色，文案含对象名与影响范围。

## 4.5 offline / stale 细则

- 「网关连不上」与「未登录」必须**两种文案、两种颜色**：
  - 连不上：红点 +「网关连不上（err.message）」→ 横幅给「重试」。
  - 未登录：灰点 +「未连接（未登录）」→ 横幅给「粘贴令牌」按钮直接开登录。
- stale 条出现条件：自动刷新=关 且 当前视图数据距今 > 5 分钟；点「立即刷新」后消失。
- 自动刷新默认 10s；**表单获得焦点时暂停自动刷新**，失焦后恢复。

# 5. 页面布局

约定：`[KPI]` 网格、`[T]` 表格、`[C]` 卡片、`[■]` 说明块、`[▓]` 日志、`[筛选]` 筛选条。桌面为主描述，移动差异见第 6 节。

## 5.1 总览（巡检首屏 · 视觉重心 = KPI + 需处理）

```
┌ view-head: 总览 │ 一眼看清供应商可用性、Key 池健康度… ──────────┐
├ toolbar: [▶ 立即健康检查] [↻ 重载配置] [🧹 清空全部冷却] ────┤
├ ⚠ 需要处理（attention）── 条目数徽章 ────────────────────────┤   ← 有则置顶
│    行：问题描述 · [一键动作] · （envgap 行可展开复制命令）      │
├ [KPI][KPI]  可用凭据 x/y │ 60 分钟失败率 x%                   │   ← 30 秒判断点
├ h4 供应商 ───────────────────────────────────────────────────┤
│    [C][C][C]  网格：状态点 · 名称 · 类型 · Key 状态 chips      │
│    （≥5 个供应商时两列；≥9 个三列）                            │
```

# 6. 响应式策略

## 6.1 断点

| 断点 | 宽度 | 布局变化 |
|---|---|---|
| **移动** | < 640px | 单列；底栏导航；表格转卡片；KPI 2 列；弹窗近全屏（宽 100%−24px） |
| **紧凑** | 640–1023px | 双列 KPI/卡片；底栏仍在；表格保留但允许横向滚动；筛选条两行 |
| **桌面** | 1024–1279px | 侧栏 240px 固定；KPI 2–4 列自适应；表格全列 |
| **宽屏** | ≥ 1280px | 内容最大 1600px 居中；供应商/用量三列；抽屉 420px |

实现上主断点保持 **1024px** 一处切换导航形态（侧栏 ↔ 底栏），640px 与 1280px 只调栅格列数，避免多套导航逻辑。

## 6.2 桌面 / 移动差异对照

| 维度 | 桌面（≥1024） | 移动（<1024） |
|---|---|---|
| 导航 | 左侧栏 240px，常显 | 底栏 4 项 + 「更多」底部抽屉 |
| 表格 | 全列，行高 40px | 转卡片（`data-label`），或关键列保留 + 横向滚动 |
| 长表单页 | 平铺 | 按 `h4.sec` 手风琴，默认展开第一节 |
| 详情 | 右抽屉 420px | 全屏层（带返回按钮） |
| 弹窗 | 居中，780/980px | 底部升起，宽 100%−24px，max-height 88vh，内滚 |
| 工具条 | 单行 flex-wrap | 允许两行；主按钮固定在行首 |
| KPI | 2–4 列 | 2 列 |
| 顶栏 | 全量控件 | 只留：连接点、主题、刷新；自动刷新收进「更多」 |

## 6.3 安全区与触控

- 底栏：`padding-bottom: env(safe-area-inset-bottom)`；页面内容同留白，**日志区不得被底栏遮挡**（内容区 `padding-bottom: 64px + safe-area`）。
- 弹窗/抽屉顶部留 `env(safe-area-inset-top)`。
- 所有可点元素最小 44×44px；表格行内小按钮（mini）可视 28px 高，但命中区用伪元素扩到 44px。
- 输入框高度 ≥ 44px（移动）/ 32px（桌面）；字体 ≥ 16px（移动，防 iOS 聚焦缩放）。
- 相邻可点元素间距 ≥ 8px。

## 6.4 横竖屏

- 竖屏为默认优化目标（手机巡检、看日志）。
- 横屏：底栏保留；KPI 可 3–4 列；表格优先横向滚动而不是继续堆卡片。
- `100vh` 一律用 `100dvh` 或 `min-height: 100dvh`，避免移动浏览器工具栏遮挡。
- 尊重 `prefers-orientation` 无需特判，但**禁止**仅横屏才出现的操作。

# 7. 可访问性

前端必须满足的硬项（验收项）：

1. **对比度**：正文 ≥ 4.5:1；大号文字（≥24px 或 ≥18.66px 粗）≥ 3:1；承担信息的图标/边框 ≥ 3:1。浅深两套主题都要验（色值与对比度见第 8 节）。
2. **语义结构**：每页唯一 `h1`（可用视图标题）；节标题 `h2`→`h4` 连续不跳级；侧栏 `<nav aria-label="主导航">`；底栏 `<nav aria-label="主要视图">`；表格用 `<table><thead><th scope="col">`；详情用 `<dl>`。
3. **键盘**：Tab 顺序 = 视觉顺序（侧栏 → 顶栏 → 内容）；弹窗打开后焦点移入并 `Tab` 循环锁在弹窗内；Esc 关弹窗/抽屉；表格行可聚焦（`tabindex=0`）并支持 Enter 打开详情；不设键盘陷阱。
4. **焦点可见**：统一 `:focus-visible` 样式（2px accent 外描边 + 2px 偏移），禁止 `outline: none`；禁用元素不可聚焦。
5. **表单**：每个控件有 `<label for>`；必填标 `aria-required`；错误文字与控件 `aria-describedby` 关联；错误态不只靠红色（配 ✕ 图标 + 文字）。
6. **状态不只靠颜色**：pill/chip 一律「色 + 文字」；连接点配文字状态；KPI 异常色配副文案。
7. **ARIA**：弹窗 `role="dialog" aria-modal="true"` + 标题 `aria-labelledby`；抽屉同理；Toast 容器 `aria-live="polite"`，错误 Toast `assertive`；倒计时/日志区 `aria-live="off"`（避免刷屏）。
8. **图片/图标**：装饰性 icon `aria-hidden="true"`；有含义的 icon 必有文字或 `aria-label`（如主题按钮 `aria-label="切换深浅色主题"`）。
9. **动画**：所有过渡 ≤ 200ms；`prefers-reduced-motion: reduce` 时关闭过渡与自动滚动（日志跟随默认改为手动）。
10. **跳转链接**：顶部提供「跳到主内容」（首 Tab 可见）。

## 8.1 设计方向

**克制、数据优先、可信赖 —— 像 Grafana 的运维面板。**

- 正文永远 `text`；次要信息 `text-2`；`text-3` 只给 placeholder 与 disabled。

### 按钮

| 属性 | 主按钮 primary | 次按钮 default | 文字按钮 ghost | 危险按钮 danger |
|---|---|---|---|---|
| 背景 | `#176B75` | `#FFFFFF` | 透明 | `#B3402A` |
| 文字 | `#FFFFFF` | `#232C2C` | `#176B75` | `#FFFFFF` |
| 边框 | 无 | 1px `#DDE2E2` | 无 | 无 |
| hover | `#0F545C` | 底 `#EAEFEF` | 文字 `#0F545C` + 底 `#E8F2F3` | `#9A3422` |
| 按下 | `#0B424A` + 下移 1px | 底 `#DDE2E2` | 底 `#CFE5E7` | `#7F2B1C` |
| 禁用 | 底 `#C3CBCB` 字 `#FFFFFF` | 底 `#F4F6F6` 字 `#8A9494` 边 `#DDE2E2` | 字 `#8A9494` | 同主按钮禁用 |

- 高度 32px（桌面）/ 44px（移动）；内边距 0 14px；圆角 6px；字号 13px/600。
- 焦点：2px `#176B75` 外描边，offset 2px。
- 破坏性操作必须用 danger 按钮 + 确认弹窗。
- 加载中：`disabled` + 前缀 ⏳，完成后恢复。

### 输入框 / 下拉 / 文本域

- 高度 32px（桌面）/ 44px（移动）；内边距 0 10px；圆角 6px；底 `#FFFFFF`；边 1px `#C3CBCB`；字号 14px。
- placeholder `#8A9494`；focus：边 `#176B75` + 2px `#CFE5E7` 外环；error：边 `#B3402A` + 下方 12px 红字。
- 禁用：底 `#F4F6F6`、字 `#8A9494`、`cursor: not-allowed`。
- 表单布局：标签上置，字段间距 16px，标签与控件间距 6px。

### 卡片 / KPI

- 卡片：底 `#FFFFFF`、边 1px `#DDE2E2`、圆角 12px、内边距 16px；hover 仅数据卡提升边框为 `#C3CBCB`，不位移。
- KPI：同卡片结构；标签 12px `text-2`；数值 26px 等宽 700（语义色随 tone）；副文案 12px `text-2`；tone 枚举 ok/warn/err/neutral。
- 暗色卡片：底 `#161D21`、边 `#2A3438`、无阴影。

### 表格

- 表头：底 `#EAEFEF`、字 11px/600 `text-2`、高 36px；行高 40px、分隔线 1px `#DDE2E2`。
- 行 hover：底 `#F4F6F6`；可点击行 `cursor: pointer` 且键盘可聚焦。
- 斑马纹不用（hover + 分隔线已够）；数字列右对齐；长文本 ellipsis + `title`。
- 空态：合并单元格、居中、12px `text-2`。

### 导航

- 侧栏项：高 36px、圆角 6px、字 13px、icon 16px；选中 = 底 `#E8F2F3` + 字 `#0F545C` + 左 2px 竖条。
- 底栏：高 56px + safe-area，背景 `#FFFFFF` + 顶部 1px `#DDE2E2`；选中 = accent 字 + 顶部 2px 指示条。
- 分组标题：11px/500 `text-3`，上下 8px。

### 弹窗 / 抽屉

- 遮罩：`rgba(19,25,28,.45)`；弹窗底 `#FFFFFF`、圆角 12px、阴影 `0 12px 32px rgba(32,42,48,.16)`。
- 弹窗头 56px（标题 15px/600 + ✕）；体可滚；底操作条 56px、主按钮右对齐。
- 抽屉：右贴边、宽 420px、阴影 `0 12px 32px rgba(32,42,48,.16)`；移动全屏。

### Toast

- 位置右上（移动顶部居中）；宽 ≤ 360px；圆角 8px；阴影 `0 3px 12px rgba(32,42,48,.08)`；字号 13px。
- ok：边 `#2F7D5C`、底 `#E6F2EC`、字 `#2F7D5C`；err：边 `#B3402A`、底 `#F8E8E4`、字 `#B3402A`；默认中性。
- 自动消失 2.5s（err 4s）；可手动关；同屏 ≤ 3 条。

### 徽章 / pill / chip

- pill：高 20px、圆角 999px、字 11px/500、内边距 0 8px；五档配色（green/red/amber/gray/blue）对应 ok/danger/warn/neutral/primary。
- chip：高 20px、圆角 4px、字 11px、底 `#EAEFEF`；用于优先级、牌价、📌 钉数。
- 语义色底一律 `*-50`、字 `*-600`（暗色用 12% 透明底 + 亮色字）。

### 提示条 / Alert

- info/ok/warn/danger 四档：左 3px 语义色竖条 + `*-50` 底 + `*-600` 字 + 图标（ℹ/✓/⚠/✕）。
- 需处理面板（attention）：warn 档底色，行高 40px，行内动作按钮用次按钮/mini。
- 页内「stale/offline」横幅用 info/danger 档，通栏。

### 日志块

- 底 `#EAEFEF`（暗 `#1C252A`）、等宽 12px/1.55、内边距 12px、高 280px（可调）、`pre-wrap`、`break-all`。
- 头部工具条 40px：状态点 + 状态字 + [暂停滚动] [复制] [清屏]。

## 这套规范的关键取舍

**信息密度优先于视觉呼吸感**：表格全列常显、卡片内边距收紧到 16px、说明长文全部收进 `<details>`，用「默认折叠 + 一键展开」换首屏判断速度——巡检 30 秒目标比「页面好看」重要。

## 前端最容易做走样的 2 个点

1. **状态用颜色独挑大梁**：pill/KPI/连接点只改颜色不加文字或图标——浅色下 warn 与 neutral、暗色下若干语义色在小字号处接近 3:1，色弱用户直接读不出状态。必须色+字同时给。
2. **移动底栏与桌面导航写成两份清单**：文案/顺序一改就不同步，且「更多」抽屉漏项。必须从同一份导航数据派生，断点只换形态不换数据。

## 需要用户拍板的 1–2 个决策

1. **请求记录 13 列的取舍**：桌面是否加「列显示设置」（默认收起 Tokens/成本/HTTP 三列），还是保持全列 + 横向滚动？前者省宽度但多一个交互，后者实现最简。
2. **积分消耗器的重启确认**：「保存改动并重启消耗器」每次必弹确认（含仅改校准值的场景），还是只在「停止账号 / 改预算上限」时才确认？前者更安全，后者更顺手。
