## 0. 一句话结论

你想要的「总控大脑」在这个项目里**已经有约七成**：执行体花名册、非交互委派、两阶段审批、
事件自动派单、模型路由与部署隔离全都在跑。缺的不是又一个框架，而是夹在中间的
**「动态选执行体」**：现在角色→工具是 `cli_tools.yaml` 里人写死的静态映射，
没有按任务特征、实时额度、历史成功率去选与换。

所以路线是**扩展 `cli_tools.yaml` + `app/services/agent/cli/registry.py`**，
不新建系统、不新建「选模型层」（11-02 文档 §3 已明确否决）。

## 1. 先澄清「总控大脑」指什么

| 层 | 现状 | 谁在做决策 |
|---|---|---|
| 任务入口 | 控制台「Agent 任务台」、`@` 直跑、多段串行、事件规则自动触发 | 人或规则 |
| **选谁干** | `roles` 静态映射 + 父模型从文字清单里挑角色 | **人（写配置）／模型凭文字** |
| 怎么干 | `run_delegation` → 适配器 → `create_subprocess_exec`（argv，不经 shell） | 代码 |
| 用哪个模型 | 每个执行体一个固定 `model`；`models`/`free_models` 只是面板标签 | 人 |
| 失败怎么办 | 自然语言提示父模型改派；批量失败即停 | 人／父模型自觉 |
| 花多少 | `cost_tier` 只是审批标签；成本只做文本附注 | 无记账 |

**「少切换」≠「免审批」。** 你这次选了「含写代码改文件跑命令」，风险档很高，
两阶段审批是必须保留的安全边界。要自动化的是**选型、切换、记账、验收**，
不是「要不要你点一下」。把这两件事混在一起，会做成你不信任的全自动系统，
和 11-02 文档 §7 的决策边界直接冲突。

另一个必须点破的事实：`enabled: true` 不等于能用。11-02 文档 §10 把
「哪些执行体是真有额度的」列为 🟡 待确认项，**至今没有答案**。
R1 实测又发现 `qoder` 的静态模型名已漂移、`codebuddy` 登录态失效（见附录 A）。
所以「自动选」的前提是先有可信的可用性与额度数据，否则只是把手动切换变成自动踩坑。

### 3.1 本次最有价值的三个新发现

1. **写操作隔离不用自己造。** claude／codex／gemini／**codebuddy**／hermes 五个 CLI
   都原生带 `--worktree`（codebuddy 是 11-06 补测），hermes 甚至写了「for parallel agents」
   并带回收子命令。你选了
   「写代码改文件跑命令」，而现有实现只有 cwd 工作区限定、**没有任何 worktree 隔离**
   ——多个 agent 并行改同一份文件会互相覆盖。启用原生参数即可，成本极低。
   同时要把 codex 适配器里的 `--skip-git-repo-check` 去掉（它绕过了 git 校验）。
2. **静态花名册会悄悄失效。** 11-06 实测：`qoder` 配置里的 `DeepSeek-Flash` 已不在
   `--list-models` 里，`codebuddy` 登录态已过期要求重新 `/login`，而两者在配置里
   都还是 `enabled: true`。这比「某个 CLI 挂了」更危险——配置看着全绿，派过去才失败。
   这正是「先有可用性数据再自动选」的论据（详见附录 A）。
3. **`claude --json-schema` 可直接服务验收。** 让执行体吐结构化结果，裁判解析成本远低于
   对自由文本做语义判定；`--bare` 还能砍掉框架税。

### 3.2 额度与框架税的实测基线（引自 10-25 文档，用作账本设计的输入）

| 指标 | 实测值 |
|---|---|
| Gemini 免费额度 | 40 分钟内约 10~12 次请求后 429 `Quota exceeded` |
| 单次委派自报 prompt | 36,853 tokens（任务正文本身约 250），codebuddy 达 45,817 |
| 框架税 | 同模型同任务：直连 4.1~5.4s，经 CLI 8.8~18.0s |
| 各免费档墙钟 | codebuddy 9.5s／qoder 29.8s（满档 56.9s）／gemini 12.2s |
| 成本 | `deepseek-v4.1-flash` `total_cost_usd = 0.0000`（真免费，不是看起来免费） |
| 满档思考 | 墙钟翻倍，且在免费渠道上更快烧额度 |

**推论**：免费额度是按「人在 IDE 里对话」设计的，撑不住「每条 agent 轮次重发全量历史」。
所以 `soft_limit` 必须显著低于实测 429 阈值（建议 8），且额度判断只能靠
「记账 + 429 信号推断」，因为多数 CLI **没有官方余额接口**。

## 4. 差距分析：愿景 → 缺口 → 落点

| 你说的愿景 | 现状 | 真实缺口 | 落点 |
|---|---|---|---|
| 给任务后自主调用其它 agent | 父模型可调 `delegate_cli`，事件可自动派单 | 角色→工具是**静态映射**；模型只是从文字清单里挑角色，不看实时状态 | `registry` 扩展：任务特征 → 候选集 → 打分选优 |
| 自动调用各工具的模型 | 每个执行体一个固定 `model` 标量 | 无候选模型集与选择策略，无法按任务切模型 | 把已有 `models` 提升为候选集 + 新增 `model_policy` |
| 什么适合就换成什么执行 | 失败只有自然语言 `_FAILURE_HINT` 劝父模型改派；批量失败即停 | 无自动换执行体、无 CLI 级连续失败隔离 | 复用 `DeploymentHealth` 思路，粒度从部署换成 CLI |
| 免费额度／积分调度 | `cost_tier` 仅标签；`cli_usage` 表**不存在**（注释写「阶段 3 落地」） | 额度账本、余额预检、窗口、日预算熔断、成本落库全缺 | 新增 `cli_usage` 表 + `quota` 配置段；`budget_cny` 从「待做」落地 |
| 不用在多个应用间切换 | `@` 直跑、多段串行、事件自动派单已打通 | **已基本达成**，剩下的是「选谁」还要人判断 | 动态路由补齐后闭环 |
| 写代码／改文件／跑命令 | cwd 限定、argv 不经 shell、`delegate_cli` 路径两阶段审批 | 无 worktree 隔离；直跑／事件 worker 两路**绕过审批卡**；`bypass` 档无逐条确认；取消不 kill 子进程；委派是裸 `create_task` 不受 `_sem` 并发闸 | 见 §6.3 |
| 干完能验、不行能换 | 只看 `result.ok`（退出码），10-25 修过 `returncode=None` 竞态 | 无质量验收／裁判，无按执行体的成功率与成本看板 | 见 §7 |

## 5. 能力矩阵 schema 增量（向后兼容，本轮只定不写解析）

**关键前提**：`registry.py:_parse_tool` 只读它认识的键，多余键被静默忽略。
所以新增字段**可以先写进配置而不破坏正在跑的网关**，等确认后再改
`CliToolConfig` dataclass、`_parse_tool` 与 `tests/test_agent_cli.py`。

```yaml
tools:
  gemini:
    # ---- 现有字段全部保持不变 ----
    enabled: true
    command: gemini
    backend: official
    model: gemini-2.5-flash
    cost_tier: free
    timeout: 300
    approval_mode: default
    models: [gemini-2.5-flash]          # 语义升级：从「面板标签」变成候选集
    free_models: [gemini-2.5-flash]

    # ---- 新增：动态路由 ----
    task_types: [mechanical-rewrite, docs, analysis]   # 建议词表见下
    strengths: {quality: 3, speed: 4, cost: 5}        # 1~5，打分用
    model_policy: prefer-free            # prefer-free / best-quality / fastest

    # ---- 新增：额度账本 ----
    quota:
      window: daily                     # daily / rolling-5h / weekly
      soft_limit: 8                     # 实测 ~10 次即 429，留 2 次余量
      reset: rolling
      probe: self-reported              # 无官方余额接口，靠 429 + 记账推断
    budget_cny: 0.0                     # 日累计上限，0 = 不限（免费档）

    # ---- 新增：写操作隔离 ----
    worktree: true                      # CLI 原生支持 -w/--worktree
    write_policy: worktree-only         # read-only / worktree-only / direct

    # ---- 新增：验收与回退 ----
    acceptance: [exit_code, diff_nonempty]   # 可验证产出优先
    fallback_role: cli-grinder          # 失败时改派的角色
    health:
      threshold: 3                     # 连续失败次数，对齐 DeploymentHealth
      ladder: [60, 300, 1800, 7200, 21600]
      decay_seconds: 3600

roles:
  cli-grinder:
    tool: gemini
    hint: 机械改写、批量整理（免费档）
    task_types: [mechanical-rewrite]   # 角色层也可加，选角色时先筛
```

**建议 `task_types` 词表**（先固定，别让模型自由发挥）：
`mechanical-rewrite`／`code-write`／`code-review`／`analysis`／`docs`／
`research`／`skill-based`／`ops-diagnosis`。

**保持不变的硬约束**：花名册对模型不可见（`delegate.py:build_schema` 把角色写死进 enum），
模型只能说「我要个写代码的」，选谁由配置决定——这条防止它绕过成本档位自己挑收费渠道，
动态路由也必须遵守，不能把工具名／模型名暴露进 schema。

## 6. 三条 P0 的设计要点

### 6.1 动态选执行体

不要做成「让大模型读一段工具介绍再挑」——那是把不确定性和 token 成本又加一层。
做成**确定性打分**：

1. 任务进来先打 `task_types` 标签（规则关键词 + 一次便宜的网关模型分类，二选一）；
2. `roles` 按标签筛出候选集；
3. 候选按 `strengths` × `cost_tier` × `quota` 剩余 × `health` 状态 × 历史成功率 打分；
4. 余额低于 `soft_limit` 或处于隔离阶梯内的直接 `gated_out`（复用路由预览的思路）；
5. 选中后从 `models` 按 `model_policy` 定模型，写入任务 brief。

这套逻辑和 `app/routing/scheduler.py` 的 `order` / `gated_out` 是同构的，
可以直接抄结构，别另发明。

### 6.2 额度账本与余额预检

- 新建 `cli_usage` 表：时间、角色、工具、模型、任务类型、`cost_tier`、
  `ok`、墙钟、自报 token、`total_cost_usd`（有就落）、失败分类、是否回退。
- 把 `adapters.py` 里 CodeBuddy／Gemini 已经解析出来的 `total_cost_usd`／`stats.*.tokens`
  **从「文本附注」改成落库**（现在只是拼进回喂正文，等于丢掉）。
- 派单前查窗口内累计：超 `soft_limit` 自动降级到下一个免费档或改走网关，
  触发 `budget_cny` 则直接停派。这正好把 11-02 文档 §8② 的「预算熔断」从待做变已做。
- 事件表已有 `cost_tokens/cost_cny` 两列，但 `agent_worker.py:_complete` 从不回填，恒为 0，
  一并接通。

### 6.3 写操作隔离与确认闸（你这次选的高风险档，必须先做）

| 措施 | 具体做法 |
|---|---|
| worktree 隔离 | 写操作任务自动加原生 `--worktree`；只读任务用 `plan`/`default` 档不加。产物以 diff 形式回读，合并由审批决定 |
| 补审批漏洞 | 把两阶段审批**下沉到 `run_delegation` 入口**，让 `@` 直跑、批量 `/delegations`、事件 worker 三路都过同一道闸；现在只有 `delegate_cli` 路径过 |

## 7. 验收与自动回退（P1）

**验收优先用可验证信号，别一上来就用模型当裁判**：

1. `exit_code` 与 stdout 可解析（已有）；
2. 写操作：`git diff` 非空、改动落在预期文件、`ruff`/`mypy`/`pytest` 通过；
3. 结构化任务：`claude --json-schema`／`codex --json` 直接给可校验对象；
4. 语义判定才用网关便宜模型（`zk-auto` 或免费档）做一次 1~2k token 的
   「完成 / 未完成 / 需返工」三分类，结果落 `cli_usage` 当成功率反馈。

**回退链**：验收不通过或失败分类为 `QUOTA`／`AUTH` → 按 `fallback_role` 换执行体，
最多 2~3 次；连续失败进 `health` 隔离阶梯，成功即半开恢复。
这套直接照抄 `DeploymentHealth` 的阈值／阶梯／衰减／半开，只是 key 从部署换成 CLI。

### E.3 ⭐ 架构结论：网关不能直连，要走反向桥接

从桌面版源码读到：
`getGatewaySecret(){return f||=randomBytes(32).toString('base64url'),f}` ——
**网关密码每次启动随机生成，只通过 `CODEBUDDY_GATEWAY_PASSWORD` 传给它自己启动的

（含 `url` / `pid` / `sessionId` / `cwd` / `lastHeartbeat`），**没有凭据文件**。

因此：
- ❌ 网关作为独立进程**拿不到密码**，直连桌面版 ACP 不可行；
- ✅ 正解是**反向桥接**：网关做总控与派单，桌面版环境里跑一个 worker
  （由桌面版启动，天然带密码），**主动向网关领任务**，再通过 ACP 执行并回传结果。
  这正是 11-02 文档里「本机在 NAT 后由本机主动拉」的同款模式，
  也复用现成的 `scripts/agent_worker.py` 长轮询骨架。

```
网关（总控：分解 / 选执行体 / 记账 / 审批）
   │  任务队列（复用 events 表）
   ▼  长轮询领任务（本机主动拉，不需要桌面版密码）
桌面版桥接 worker（带随机密码 → 本地 ACP）
   ├─ 复用已有会话：session/load + session/prompt
   └─ 另开新会话：session/new + session/prompt
   │  回传结果
   ▼
网关汇总 / 验收 / 记账
```

⑤ 网关要掌握**每个应用的 AI 能力**再派活；⑥ 免费积分模型**中途中断**要能接管续跑。

### F.1 本机实际在跑什么（PowerShell 进程 + 端口归属 + HTTP 探测）

⚠ 沙箱环境本轮报 `center 规则快照不可用`（fail-closed），Bash 通道不可用，

### F.2 ⭐ 最大发现：editor_sdk 是 231 个工具的免鉴权 MCP

`http://127.0.0.1:39099/mcp`，标准 MCP（JSON-RPC 2.0，`protocolVersion 2024-11-05`），
`initialize` 返回 `serverInfo: editor-sdk 1.0.0`，`tools/list` 返回 **231 个工具**：

| 类别 | 数量 | 代表能力 |
|---|---|---|
| SHEET | 67 | 单元格/样式/边框/合并、图表、透视表、条件格式、数据验证、公式试算与一致性审计、AI 编辑回滚 |
| DOC | 57 | 文本/段落/表格/图片/批注/脚注、命名样式、Markdown 与 HTML 插入、公式、文档对比、AI 编辑回滚 |
| SLIDE | 约 100 | 幻灯片/形状/表格/图表/动画/主题/节/备注/参考线 |
| 通用 | 7 | `open_file`、`save_file`、`create_sheet`、`create_doc`、`create_slide`、`close_file`、`get_pool_status`、`shutdown` |

**为什么这是"操控桌面版"的正路**：
- 免鉴权、标准协议、工具描述是中文的，**不用模拟鼠标点击**；
- 覆盖 Office 三件套，正是运营者日常最需要的"让 AI 干活"场景；
- `get_pool_status` 说明有编辑器池，可并发；`list_recent_ai_edits` / `undo_ai_edit`
  提供**可回滚**，天然适合"中断接管"。

⚠ `browser-use-mcp-server`（64403）也走 MCP，但 `POST /mcp` 返回 401
`missing or invalid token`，token 待从 CatPawAI 配置里定位（不落文档）。

### F.3 能力画像：不要手写，直接问出来

运营者要求"网关要知道每个应用的 AI 能力具体怎么样"。做法分三层，**全部自动发现**：

| 层 | 发现方式 | 产出 |
|---|---|---|
| MCP 类（editor_sdk / browser-use） | `initialize` + `tools/list` | 工具名 + 中文描述 + `inputSchema` → 直接映射成任务类型标签 |
| CLI 类（claude/codex/gemini/hermes/codebuddy/qodercli） | `--help` + 实测 | 无头入口、协议（ACP/MCP/本地服务）、模型清单、worktree、结构化输出 |
| 模型层 | 网关 `/v1/models` + 各 CLI `--list-models` | 模型 id、是否免费、上下文、思考档 |

画像字段建议：`task_types` / `tools`（MCP 工具数或类别）/ `models` / `free_models` /
`quota` / `latency_p50` / `success_rate` / `interruptible`（是否支持中断续跑）。
**画像带 TTL 缓存**（CLI 帮助 5 分钟、MCP 工具列表 10 分钟），过期自动重取，
禁止手抄清单——附录 A 的 `qoder.model` 漂移就是手抄的代价。

### F.4 任务空间：所有 AI 在同一个目录里干活

```yaml
task_space:
  root: "<repo>/.workbuddy-ai/taskspaces"
  layout: "{task_id}/"          # 一任务一目录
  subdirs: [inputs, work, outputs, logs]
  state_file: state.json        # 进度与产物清单（接管用）
  lock_cwd: true                # 所有执行体 cwd 强制锁在任务空间
  read_only: ["<repo>"]         # 主仓库只读，避免误改
  write_only: ["{task_space}"]  # 只允许写任务空间
```

落地要点：
- 每个执行体派单时 `cwd` 一律指向任务空间；桌面版 ACP 的 `session/load` / `session/new`
  也传同一个 `cwd`。
- 产物统一落 `outputs/`，日志落 `logs/`，`state.json` 记步骤、产物、执行者、进度。
- 验收只看 `outputs/` 与 `git diff`，不依赖任何执行体的自述。
- 好处：隔离、可回放、**可接管**（见 F.6）。

### F.5 统一权限：网关一档，所有执行体跟随

```yaml
permission:
  mode: bypass              # bypass / approval，全局一档
  scope: task_space_only    # ⚠ bypass 只在任务空间内生效
  deny_outside: true        # 任务空间外一律拒绝
  audit: true               # 每次写操作留痕
```

各执行体的映射（**只在任务空间内**生效）：

| 工具 | 绕过参数 |
|---|---|
| claude | `--dangerously-skip-permissions` |
| codex | `--dangerously-bypass-approvals-and-sandbox` |
| gemini | `--approval-mode yolo` |
| qoder | `--permission-mode bypass_permissions` |
| codebuddy | `-y` / `--permission-mode bypassPermissions` |
| hermes | `--yolo` |

**必须保留的安全边界**（不能因为"简单"就丢掉）：
1. bypass 的 `cwd` 必须是任务空间，主仓库只读；否则一次误操作能改掉生产配置。
2. 现有 `registry.py:_APPROVAL_MODES` 硬拦 yolo/auto，需新增
   `permission.mode` 一层由网关统一下发，而不是让每个工具配置各自开 bypass。
3. 审计必须留：谁在哪个任务空间、调了什么、改了哪些文件。

### F.6 中断接管：能不能接管，取决于产物有没有落盘

免费积分调用的强模型随时可能 429 / 额度耗尽 / 超时中断。接管分三级：

| 级别 | 场景 | 做法 |
|---|---|---|
| L1 同工具换模型 | 会话还在、只是模型不可用 | codebuddy `--fallback-model`、hermes `fallback`、claude `--model` 换档；**上下文不丢**，代价最小 |
| L2 跨工具接管 | 会话没了/工具整体不可用 | 读 `state.json` + `outputs/` + `handoff_brief`，重新派单给另一执行体；**上下文重建**，可能丢隐含状态 |
| L3 人工介入 | 产物没落盘 / 状态不可迁移 | 标记 `needs_human`，保留现场，不反复重试烧额度 |

**分水岭是产物落盘**：只要每一步都写进任务空间，L2 就能接管；
如果只在会话内存里推进，工具一断就全丢。所以 F.4 的 `state.json` 不是可选项。

`state.json` 最小结构：

```json
{
  "task_id": "20261107-001",
  "goal": "把这份表整理成月报",
  "steps": [
    {"id": 1, "status": "done", "by": "workbuddy-desktop", "artifact": "outputs/raw.xlsx"},
    {"id": 2, "status": "running", "by": "editor-sdk", "note": "正在生成图表"}
  ],
  "artifacts": ["outputs/raw.xlsx"],
  "handoff_brief": "已完成数据清洗；下一步生成图表并写入 outputs/report.xlsx",
  "interruptible": true
}
```

**不可迁移状态要显式标注**：未落盘的会话记忆、工具内部临时变量、未保存的编辑器缓冲。
接管前先 `save_file` / `close_file`，再换执行体。

### F.7 多账号扩大免费额度

同一应用多账号 = 多份配置目录/profile（claude `--settings`、codex `-c`、
codebuddy `--settings`、qoder 独立 profile）。网关侧按账号池化：
`account_id` + `quota`（窗口/已用/重置时间）+ `cost_tier`。
派单时优先选**剩余额度最多且未隔离**的账号，额度耗尽自动切下一个。
⚠ 免费额度是账号级资源，必须进账本（R2 的 `cli_usage`），否则会重复踩"派过去就 429"。

### F.8 本轮结论与下一步

1. **能立刻用的通道**：editor_sdk 39099（免鉴权 MCP，231 工具）> WorkBuddy 51489/51497
   （需密码）> CatPawAI 64403（MCP，需 token）> 其余（无 HTTP 口）。
2. **Qoder 当前不可用**（没进程），Codex/claude 走 CLI 不走本地服务，ZCode 走 IPC。
3. **下一步优先级**：① 把 editor_sdk 接成网关的 `backend: mcp` 执行体（只读工具先跑）；
   ② 任务空间 + `state.json` 落地；③ 统一权限层（bypass 仅任务空间）；
   ④ 能力画像自动刷新；⑤ 中断接管三级策略。
4. 本轮仍未改 `app/`、未重启网关；接入需要一次重启，动手前跟运营者确认时点。

### G.1 为什么加一条新后端，而不是塞进 CLI 适配器

现有链路是「拉起子进程 → 读 stdout」，而 MCP 是「POST JSON-RPC → 读 SSE/JSON」，
**没有进程可等**。硬套适配器会出现两种坏结果：要么伪造一个假命令，
要么把 HTTP 调用塞进 `build_command` 再被 `resolve_command` 当命令解析。
所以按 `backend` 分流，其余（角色、审批、超时、失败分类、记账）全部复用。

## 附录 H：任务空间与统一权限落地（2026-11-07 09:3x）

### H.1 任务空间

新增 `app/services/agent/taskspace.py`，目录约定：

```
<workspace>/.taskspaces/<task_id>/

    work/      执行体临时工作区
```

## 附录 I：租约防冲突与直跑接入（2026-11-07 09:5x）

运营者的三条要求：**既要智能、又要给人工干预留空间、小白体验要好，
最重要的是各模型/工具之间不能打架**。

### I.1 「不打架」靠租约，不靠自觉

同一任务空间**同一时刻只允许一个写者**。实现是 `state.lock` 文件 +
`O_CREAT|O_EXCL` 原子创建（跨进程安全，不依赖内存锁）：

- 锁内容是 JSON：`{"owner": 会话号, "expires_at": 时间戳}`；
- 过期租约（默认 1900s，覆盖执行体 1800s 上限）可被抢占，避免死锁；
- **同一 owner 重入视为已持有**，不会自己把自己锁在门外；
- `release` 只有持有者能释放，不会误删别人的锁；
- 拿不到锁时返回一句中文：「这个任务空间正被 X 使用，为避免两边互相覆盖，
  本次没有派单。等它完成后再试，或者换一个任务重开一个空间。」——
  这就是「小白体验」：告诉他发生了什么、下一步怎么做。

### I.2 直跑接入，三个入口不再各走各的

`_delegation`（`@` 直跑 / `followup`）现在与 `_delegate_cli`（模型自主派单）
共用同一套逻辑：

1. 开任务空间（`taskspace.create`）；
2. 抢租约（`taskspace.acquire`）；
3. 拿到 → `cwd` 指向任务空间，`allow_bypass` 按网关权限档；
4. 抢不到 → 会话直接标 `failed`，错误信息是上面那句中文，不空转；
5. `finally` 释放租约（异常、取消、拒绝都会释放）。

### I.3 给人工干预留的空间

| 干预点 | 现状 |
|---|---|
| 派单前 | `approval` 档保留两阶段审批卡；`bypass` 只在任务空间内自动放行 |
| 执行中 | 会话可取消（状态如实记 `cancelled`） |
| 冲突时 | 明确告知占用者与下一步，不静默失败 |
| 事后 | `GET /zkadmin/agent/taskspaces` 可查每个空间的进度、步骤数、产物数 |
| 接管 | `state.json` 的 `handoff_brief` 留给下一个人/执行体 |

## 附录 J：任务空间页面与「网关 vs 桌面版」（2026-11-07 10:0x）

### J.1 页面：`/ui/taskspaces`

运营者要求「小白使用体验要良好」。之前任务空间只有 API，不熟悉的人看不到
「我的任务在哪个文件夹、做到哪一步」。现在补了一个纯静态页面：

- **列表**：任务目标、编号、创建时间、步骤数、产物数、占用状态（空闲 / 占用中）；
- **查看进度**：展开读 `state.json`，显示步骤、产物、交接说明；
- **打开文件夹**：调系统文件管理器，直接看产物；
- **释放占用**：执行体崩了但租约没到期时的人工干预（有二次确认）；
- **空状态**：「还没有任务空间。让 AI 干一次活，它会自动创建。」——
  不给一个空白页让人猜。

新增三个端点（都在 `require_admin` 之后）：

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/zkadmin/agent/taskspaces/{id}` | 读进度（步骤、产物、交接说明） |
| POST | `/zkadmin/agent/taskspaces/{id}/release` | 人工强制释放租约（返回原占用者） |
| POST | `/zkadmin/agent/taskspaces/{id}/open` | 在文件管理器打开（仅本机，路径经 `is_inside` 校验） |

安全细节：`open` 只接受任务空间根内的目录；打开动作放 `asyncio.to_thread`，
不阻塞事件循环；非 Windows 平台用 `shutil.which` 找绝对路径再启动。

### J.2 这些功能在网关里，还是要有桌面版？

**现状：全部在网关 + 网页控制台，没有独立桌面客户端。**
桌面版（WorkBuddy / CodeBuddy / Qoder / CatPawAI…）在这套架构里是**执行体**，
不是总控；它们被网关调用，不是并列的入口。

两种形态的取舍：

| 维度 | 网关 + 网页（现状） | 独立桌面版 |
|---|---|---|
| 安装 | 零安装，浏览器打开 | 要打包、签名、自动更新 |
| 跨设备 | 手机/平板也能看、也能批 | 只能装了的机器用 |
| 与网关同源 | 无跨进程鉴权，改完即生效 | 要处理端口发现、令牌、版本错配 |
| 常驻/通知 | 标签页容易被关，通知弱 | 托盘常驻、系统通知、开机自启 |
| 本地文件 | 拖拽/打开目录受浏览器限制 | 原生支持 |
| 维护成本 | 一份代码 | 多一套壳 + 发版链路 |
| 新增入口 | 不加 | **又多一个要切换的应用**（与初衷相反） |

**建议：不做独立桌面版，做「网页控制台 + 极薄托盘壳」。**
托盘壳只做四件事：开机自启、托盘图标、系统通知（「有任务要你拍板」）、
一键打开控制台。项目里已有 `scripts/tray_launcher.py` 与托盘菜单的中文守门，
复用它比新写一个 Electron 应用便宜一个数量级。

理由：运营者的核心痛点是「不用在多个应用之间切换」；再加一个桌面应用，
等于又造了一个入口。网页 + 托盘 + 通知能拿到 90% 的桌面体验，
维护成本只有 10%，且**控制台始终是唯一真相源**。

## 附录 K：三条派单路径统一 + 洁癖（2026-11-07 10:2x）

### K.1 一条逻辑，三处调用

之前「建任务空间 → 抢租约 → 冲突早退」在 `_delegate_cli`、`_delegation`、
`_delegation_batch` 各写了一遍，三份几乎相同但措辞不同——这是最容易长歪的形态。
现在收敛成一个方法：

```python
def _enter_task_space(self, run, *, goal) -> tuple[TaskSpace | None, Path, bool, str]
```

返回 `(空间, 工作目录, 是否允许 bypass, 错误说明)`；**失败呈现留给调用方**，
因为工具结果、会话状态、事件回执三种界面的说法本来就不一样。

- 整批**共享一个任务空间**：先让 A 查、再让 B 审，产物落在同一处；
- goal 取各段任务拼接（截断 200 字），便于事后看出这批在干什么；
- 串行执行不变（免费额度本来就紧，并发只会互相挤成 429）；
- 抢不到租约时整批不执行，会话标 `failed` 并给出中文原因。

### K.3 事件 worker

`scripts/agent_worker.py` 的 `run_once` 现在也走任务空间：

- 事件**显式指定了 `cwd`** 时保持原行为（尊重规则里的目录），不建空间；
- 没指定时按 `agent_task_space` 建空间，owner 用 `event-<编号>`，便于在页面上对上是哪条事件；
- 抢不到租约 → 直接 `_complete(ok=False)` 把原因写回事件表，不空转、不重试；

## 附录 N：开放写类 MCP 工具（2026-11-07 11:5x）

### N.1 为什么不是「再加几个执行体」

编辑器是**有状态**的：`create_sheet` / `open_file` 返回 `file_id`，后续读写都要带着，
最后 `save_file` + `close_file`。一个执行体只绑一个工具（`mcp_tool`）根本编排不了
「建表 → 写入 → 保存」这种四步流程。

所以新增通用入口 `mcp_call`：模型自己选工具、自己给参数，像人用编辑器一样一步步来。

### N.2 白名单就是权限清单

`cli_tools.yaml` 的 MCP 执行体新增 `mcp_tools` 列表，只有列进去的工具才能被
`mcp_call` 调到；schema 的 `enum` 也只列这些名字，模型编不出来。

现役白名单（9 个）：

```
get_pool_status, save_file, close_file,
create_sheet, create_doc, create_slide,
sheet_get_sheet_info, sheet_get_cell_data, sheet_set_range_value
```

**`open_file` 的坑与正解**（同一轮里被推翻两次，如实记录）：
它默认只是「开始加载」就返回，紧接着读会报 `No workbook open`；
先怀疑是分块流式、还试过先连 `/stream` 再打开，都不对。
翻完整参数表才发现有 `wait` 参数——传 `true` 会阻塞到真正打开完成。
现在 `mcp_call` **自动补这个参数**（模型不用记），所以它留在白名单里。
教训：**先读完参数表，再怀疑协议**。

### N.3 安全边界：路径只能在任务文件夹里

`mcp_call` 的 `arguments` 里凡是 `file_path` / `path` / `image` / `image_path`，
一律要求落在 `.taskspaces/` 之内，越界直接拒绝并给中文提示：

> 参数 file_path 指向任务文件夹之外（…），为安全起见拒绝执行。
> 请把文件放到当前任务的 outputs/ 或 work/ 目录下。

这条比"相信模型"可靠：即使模型给了一个绝对路径指向主仓库，也写不进去。

### N.4 实测闭环（真跑，不是 mock）

```

sheet_get_sheet_info  → sheet_id=000001
sheet_set_range_value → 写入 4 个单元格（项目/金额/总控大脑/128.5）
```

## 附录 P：工具调用账本（2026-11-07 14:3x）

### P.1 为什么用追加文件，而不是新表

网关的 `usage_records` 记的是**模型请求**；工具调用（`mcp_call`）是另一类开销，
需要单独记。但动核心库的表结构要迁移、要重启、要担心历史数据——风险不成比例。

所以用追加式 JSONL：`<data_dir>/mcp_usage.jsonl`，一行一条。
- 零迁移、零重启风险；
- 坏了只坏一行，读的时候跳过；
- 单人单机量级（一天几十到几百条）完全够；
- 直接用文本编辑器也能看。

### P.2 记什么、不记什么

记：时间、工具名、服务名、会话号、任务空间、成功与否、耗时、错误摘要（截断 200 字）。

**不记参数内容**——参数里可能有文件路径、业务数据、甚至密钥；
账本是给人看的，不该变成第二个数据泄露面。有测试专门守这条
（`test_record_does_not_leak_arguments`）。

记账失败**绝不影响主流程**：`record()` 自己吞掉所有 `OSError`，
不能让"记不上账"把正在跑的任务搞挂。

### P.3 入口

- `GET /zkadmin/agent/mcp-usage?limit=50` → `{recent: [...], summary: [...]}`；
- 任务空间页面顶部新增「最近工具调用」区块：成功/失败、工具名、耗时、时间。
  没有记录时显示「还没有调用记录。AI 用编辑器工具后这里会出现。」

## 附录 Q：统一模型清单与实测成本（2026-11-07 傍晚）

运营者要求：「能够获取每个工具的所有模型以及价格」。这一轮把它做成了
**一个可核实的视图**，而不是一张手抄表。

### Q.1 价格必须分层，否则一定骗人

| 来源 | 含义 | 数据出处 |
|---|---|---|
| `tariff` | 网关模型的**真实牌价** | `models.yaml` 部署级 `input_cost_per_mtok` / `output_cost_per_mtok` |
| `observed` | 外部 CLI 的**实测成本** | 每次调用自报的 `total_cost_usd`，按「工具/模型」累计 |
| `subscription` | 订阅或免费额度内 | 只有档位，单价未知 |
| `unknown` | 什么都没拿到 | 如实标未知 |

**硬规则：拿不到价格就写「未知」，绝不用 0 或估算值填充。**
写 0 会被读成「免费」，这是最危险的一种谎——运营者会据此把重活派过去。
