# 服务器怎么同步代码

> 从 `AGENTS.md` 拆出（2026-10-25）：规则文件超过 65,536 字节的载入预算，
> 流程性内容挪到这里，正文未改。

**`/opt/zkai` 现在是真正的 git 检出，同步走 git，不要再手工挑文件传。**

```bash
# 本地：改完 → 提交 → 推。**本机走 SSH 推拉**（origin 已是
#   git@github.com:K2951314/zk-ai.git）：2026-10-25 实测 `ssh -T git@github.com`
#   报 `Hi K2951314!`（~/.ssh/id_ed25519），fetch 与 push --dry-run 全通。
#   HTTPS 直连反而不可靠（代理没开时 Connection was reset / 443 超时），
#   别再改回 HTTPS，更不必依赖 10808 代理在线。
git push origin main

# 服务器（现役「腾讯」是 root 直连，无需 sudo；仓库文件属 www-data）
git -c safe.directory=/opt/zkai -C /opt/zkai fetch origin main
git -c safe.directory=/opt/zkai -C /opt/zkai reset --hard origin/main
cd /opt/zkai && git -c safe.directory=/opt/zkai ls-files -z | xargs -0 chown www-data:www-data
systemctl restart zkai            # 配置热加载，但换代码要重启
```

**本机 PowerShell 发起 SSH 的三个坑（2026-11-19 实测）**：
① `ssh` 不在 PATH，用全路径 `C:\Windows\System32\OpenSSH\ssh.exe`；
② 远程命令里的 `$(date ...)` 会被 PowerShell 本地解析——整段用单引号
here-string `@'...'@` 包起来原样传；③ 传文件用 base64 管道
（`[Convert]::ToBase64String(...)` → 远程 `base64 -d`），字节级精确，
别用 `>` 重定向（pwsh 默认写 UTF-16）。

⚠ **chown 那行必须先 `cd /opt/zkai`**（2026-10-24 实测踩坑）：`ls-files` 输出的
是**相对路径**，在 SSH 登录的家目录里跑 `xargs chown` 会整批
`cannot access`——且它排在 `&&` 链中间，失败会**静默跳过后面的 restart**，
表现为「代码同步了但服务还在跑旧版」。

- `reset --hard` 只动**被跟踪**的文件：`config/*.yaml`、`.env`、`data/`、`__pycache__`
  全在 `.gitignore` 里，**不会被覆盖**。服务器上现役配置永远是它自己的那一份，
  所以 `config/models.yaml` 这类**不受版本控制、但影响行为**的文件要单独同步
  （本机 scp 不可用，用 `ssh host "cat > /tmp/x" < 文件` 或 base64 管道）。
- 服务器监听 **8318**，本机是 8317 —— 探活别打错端口。
- **服务器连不上 GitHub 时的备用通道：git bundle 经 SSH 运输**（2026-10-24
  实测，GnuTLS -110 / 443 超时）：本地
  `git bundle create x.bundle <服务器HEAD>..main` →
  `ssh tandian211 "cat > /tmp/x.bundle" < x.bundle` → 服务器
  `git fetch /tmp/x.bundle main:refs/remotes/origin/main` 后照常
  reset/chown/restart。**这仍是 git 同步**（完整对象与引用），只是运输通道
  换了——比手工挑文件传强在服务器 HEAD 仍然真实可查。纯文档改动可以跳过
  restart。
- **现役服务器是 `腾讯`（115.159.87.18，用户 root，SSH 别名 `腾讯`，
  key `~/.ssh/id_ed25519`）**——2026-11-16 从 211 迁来（见文末「换服务器实战核对」）。
  root 直连，命令里的 `sudo` 可省；git 仍需 `-c safe.directory=/opt/zkai`（文件属 www-data）。
  历史：211.159.174.204（别名 tandian211）与更早的 120.53.28.29 均已停用，别连错。
- 服务器本地分支 2026-10-21 已从 `master` 改名 `main` 并 `--set-upstream-to=
  origin/main`（之前 `reset --hard origin/main` 留下的命名不一致，已对齐）。
- **服务器 origin 必须用 HTTPS，不能用 SSH**（2026-10-21 实测）：origin 曾是
  `git@github.com:...`，但服务器 `ubuntu` 用户**没有配任何 GitHub deploy key**
  （`~/.ssh` 只有 known_hosts），于是 `sudo git fetch` 永远
  `Permission denied (publickey)`——「同步走 git」其实从没真正拉成功过，
  全靠手工传文件。这个仓库是**公开仓库**（本机 `git ls-remote
  https://github.com/K2951314/zk-ai.git` 无需认证即可读），已改
  `git remote set-url origin https://github.com/K2951314/zk-ai.git`，
  fetch 即刻恢复。**push 仍走本地（本机有 key），服务器只需要 fetch**，
  所以服务器不必配 push 权限。若哪天仓库转私有，HTTPS 拉取也要 token，
  到时给 ubuntu 配一个 read-only deploy key 再切回 SSH。
- 同步前先留备份：`sudo tar czf /var/backups/zkai/code-$(date +%F-%H%M).tgz -C /opt/zkai
  --exclude=.venv --exclude=data --exclude=.git --exclude=__pycache__ .`
- **判断差异别凭 mtime**：本地工作区是 CRLF（`core.autocrlf=true`），服务器是 LF，
  直接比 sha256 会满屏「不同」。要按**归一化换行后**的内容比，或用
  `git hash-object` 把两边都过一遍 clean 过滤器再比。

## 反向同步：把服务器环境拉回本地（2026-10-26）

只同步**不被 git 跟踪**的那部分：`.env`、`config/*.yaml`、
`/var/lib/zkai/zkai.db`、`/var/lib/zkai/burner/burn_state.json`。
交付代码仍走 git，别顺手 scp `app/`。

```bash
# 1) 先拉到暂存区比对，别直接覆盖本地现役配置
ssh tandian211 'sudo cat /opt/zkai/.env' > exports/server-sync-20261026/.env
ssh tandian211 'sudo cat /opt/zkai/config/models.yaml' > exports/server-sync-20261026/config/models.yaml

# 2) 数据库先用 backup API 取一致快照，再传（别直接 cp 正在写的库）
ssh tandian211 "sudo python3 -c 'import sqlite3; s=sqlite3.connect(\"file:/var/lib/zkai/zkai.db?mode=ro\", uri=True); d=sqlite3.connect(\"/tmp/zkai-snapshot.db\"); s.backup(d); d.close(); s.close()'"
ssh tandian211 'sudo cat /tmp/zkai-snapshot.db' > data/zkai.db
ssh tandian211 'sudo rm -f /tmp/zkai-snapshot.db'

# 3) 覆盖库之前：停网关、备份 data/、删掉旧的 -wal/-shm
#    否则旧 WAL 帧会回放到新库 → database disk image is malformed
```

**`.env` 必须按 key 合并，不能整份替换**：服务器那份是生产运行参数
（`ZKAI_HOST/PORT=127.0.0.1:8318`、`ZKAI_DATA_DIR=/var/lib/zkai`、
`ZKAI_DATABASE_URL`、`ZKAI_BURNER_DIR`、`ZKAI_REQUEST_TIMEOUT=25`、
`ZKAI_EXPOSURE=server`、`ZKAI_PUBLIC_BASE_URL=https://211.159.174.204/zkai`），
带进本机就全错了——尤其 `ZKAI_PUBLIC_BASE_URL` 会让本机自认公网实例。真正要拿的是密钥：
2026-10-26 那次服务器独有的是 `OPENROUTER_API_KEY`、`STEPFUN_API_KEY_02`
（本机 providers.yaml 已在引用、值为空），本地独有的 `STEPFUN_API_KEY`
要保留。全程按字节读写并保持 CRLF（`read_text()` 会把换行悄悄归一化）。

## 换服务器实战核对（2026-11-16，211→115.159.87.18）

这次迁移应用代码没问题，坏的都是**网关对外地址 + 共享 Caddy 配置**。逐条核对：

### 1. `ZKAI_PUBLIC_BASE_URL` 是面板地址的真相源
- `/opt/zkai/.env` 的 `ZKAI_PUBLIC_BASE_URL` 迁移时被带成了旧 IP，
  「客户端接入」面板读的是 `/zkadmin/chatgpt` → `deploy.client_base_url`，
  它自动补 `/v1` 给客户端。改这一个变量即可，**不要带 `/v1`**（避免双 `/v1`）。
- **改完 `.env` 必须 `systemctl restart zkai`**：文件监听器只看 `config/*.yaml`，
  不看 `.env`，不重启内存里还是旧值。改前备份 `.env.bak-<日期>`。
  （`config.yaml` 的 `deploy:` 段 2026-11-19 起可热更，但 `.env` 这条不行——见 §5。）
- 本机开发 `.env`（第 52 行）与 `~/.codex/config.toml` 的 `base_url`、`docs/服务器同步.md`
  示例值可能仍是旧 IP，按需要一并更新（本机那份不影响服务器面板）。

### 2. 公网入口必须用被信任的证书，否则 SDK 全废（关键权衡）
- **根因是证书，不是协议**：旧机 `https://211.159.174.204/zkai/v1` 之所以好用，
  是因为它用的是 Let's Encrypt 签发的**真实 IP 证书**（SAN=`IP Address:...`，
  6 天短期，系统信任，curl 带校验正常）。新机继承的是 Caddy `tls internal`
  **自签证书**，OpenAI 兼容 SDK（Codex / Claude Code / 各类 App）配 https 直接
  `CERTIFICATE_VERIFY_FAILED`。
- **最终解法（2026-11-16 已落地）**：给新 IP 申请 Let's Encrypt IP 证书，
  切回 https。Caddyfile 里 https 站点改：
  ```
  https://115.159.87.18 {
      tls force_automate {
          issuer acme {
              profile shortlived      # IP 证书强制要求 shortlived（约6天）
          }
      }
      ...
  }
  ```
  IP 证书要求：`shortlived` profile + **只能用 http-01 / tls-alpn-01 验证**
  （不能 DNS）；80/443 公网可达。Caddy v2.10.2 支持。签发全自动、每几天续期。
  验证成功日志：`certificate obtained successfully`，之后
  `curl https://<新IP>/zkai/health`（带校验）返回 200。
- **过渡期的坑（已废弃，仅留档）**：证书没就绪时曾把公网 API 配成
  `http://<IP>/zkai/v1`，并给 `/zkai/*` 开不跳转的纯 HTTP 站点；一旦客户端配 http
  而 Caddy 又把 http 全 308 到 https，SDK 报 `API Error: 308 upstream_error`。
  这是反代跳转冲突，不是网关故障。
- **证书落地后要收紧 http（2026-11-16 已完成）**：删掉手写的 `http://` 站点块，
  交给 Caddy 的 `auto_https` 接管 80 端口——它自动 308 到 https，**并自动放行
  ACME http-01 挑战**（手写 catch-all redir 会干扰挑战路径，别自己写）。
  验证：`caddy validate` 日志应出现
  `http.auto_https: enabling automatic HTTP->HTTPS redirects`。
  效果：`http://<IP>/zkai/v1` 不再明文传输 API token。

### 2b. 网关端口必须只监听回环（2026-11-16 加固）
- systemd unit 的 `ExecStart` 曾写 `--host 0.0.0.0`，**覆盖了 `.env` 的
  `ZKAI_HOST=127.0.0.1`**，于是 `http://<公网IP>:8318/*` 可绕过 Caddy 直接访问
  （`/v1` 与 `/zkadmin` 有 401，但 token 明文、且多一个攻击面）。
- 已改成 `--host 127.0.0.1`：公网只留 Caddy 的 https 入口（443 → 127.0.0.1:8318），
  同机服务（tandian 的 `ZKAI_API_BASE_URL=http://127.0.0.1:8318/...`）不受影响。
- 动手前先确认没有配置引用「公网IP:8318」：
  `grep -rn '<公网IP>:8318' /opt/zkai /opt/tandian /etc/tandian.env`（应为空）。
- ⚠ 智能询价 8001 仍是 `0.0.0.0`，若手机端不用直连端口，同样可收紧。

### 3. `/zkadmin/*` 与 `/admin/*` 必须分离
- 旧机 Caddyfile 有 `@zkadmin path /zkadmin /zkadmin/*` 反代 8318；新机漏了导致 404。
- `console.js:302` 把 `/admin/xxx` 改写成 `/zkadmin/xxx`（2026-10-08 迁移后的约定）。
- `/admin/*` 必须完整归智能询价 8001，**不要按 `Sec-Fetch-Mode` 分流**——
  浏览器加载 CSS/JS 就是 `no-cors`，分流会把静态资源错送给网关 8318 导致全 404。

### 4. 配置"新旧"不能只看 mtime，要剥注释做语义 diff
- 本次实测：服务器 `config.yaml` mtime 比本地新，但语义上服务器是 Oct-15 旧版
  （缺 stream_idle_timeout / max_credentials 9→3 事故修复 / attempt_timeout_floor），
  本地 Nov-13 才是最新；`burner.yaml` 同理（本地有 disabled+额度翻倍，服务器没有）。
- `models.yaml`/`providers.yaml` 是**双向分叉**：本地多 workbuddy/wb-hy3/hy4free、
  限额翻倍、stepfun-02；服务器只比本地多了 11-14 删的华为云 MaaS（`HW` provider +
  `deepseek-v4.1-flash-1017-HW`），且本地从来没配过 HW（本地的"华为"是 CodeArts CLI，另一回事）。
- 判新旧的正确姿势：`yaml.safe_load` 后逐条目 diff（剥缩进/注释噪音），别用
  `diff` 的行号或 mtime。Bak 文件名（如 `.bak-20261114-delHW`）是重要线索。

### 5. `reload_config()` 的缺口已修（2026-11-19）
- 旧缺口（新 Settings 不写回 `container.settings`、`client_base_url` 停在启动值）
  已在 2026-11-19 热加载完整性重构中修复：runtime 字段原地 setattr 生效，
  `deploy:` 段（含 `public_base_url`/`exposure`）现在**改 config.yaml 即热更**。
  启动期字段（host/port/db 等）改了不应用，在 `/health` 的 `config.restart_required`
  点名「需重启」。真机实证：改 `public_base_url` 兜底值，reload_count +1、无报错。
- **但 `.env` 仍要重启**：文件监听器只看 `config/*.yaml`，不看 `.env`。
  面板地址的真相源是 `.env` 的 `ZKAI_PUBLIC_BASE_URL`，改它之后仍须
  `systemctl restart zkai`（见 §1）。别把「deploy 段能热更」误读成「改 .env 也行」。
