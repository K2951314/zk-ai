# 免费档执行体接入实测（2026-10-25）

一次性记录：把 Qoder / CodeBuddy / Gemini 三条"免费额度"CLI 接进 `delegate_cli`，
并实测它们到底能不能当劳动力。结论已沉淀进 `AGENTS.md` 与 `config/cli_tools.example.yaml`。

## 结论先说

1. **能干活，但只能干低频批量活。** 免费额度是按"人在 IDE 里对话"设计的：
   一次委派 CLI 自报 **prompt 36,853 tokens**（任务正文本身约 250 tokens），
   40 分钟内十几次请求就把 Gemini 免费配额打空（429 `You exceeded your current quota`）。
2. **框架税很重。** 同一模型、同一任务：直连 4.1~5.4s，经 CLI 8.8~18.0s。
   多出来的是进程启动（~2s）+ CLI 自己的路由/分类调用 + 系统提示与工具清单的 token。
3. **三条路径里只有 Gemini 是"官方正门"。** CodeBuddy/Qoder 是订阅复用（CLI 登录态
   与桌面端不共享，首次必须交互式 `/login` / `qoder login`），ToS 与断供风险自负。

## 实测数据

任务：把 5 条商品描述改写成固定字段的 JSON 数组（可判定对错）。模型 `gemini-2.5-flash`。

| 臂 | 次数 | 墙钟(s) | 合法 JSON | 条目 | 输出字符 | CLI 自报 token |
|---|---|---|---|---|---|---|
| 直连 OpenAI 兼容端点 | 1 | 4.9 | 是 | 5 | 288 | 端点未回报 |
| 直连 | 2 | 4.6 | 是 | 5 | 288 | — |
| `delegate_cli`（gemini） | 1 | 18.0 | 是 | 5 | — | 入 36,853 / 出 351 |
| `delegate_cli` | 2 | 8.8 | 是 | 5 | — | 入 36,853 / 出 351 |

后两行是修复 `runner` 退出码竞态之前的记录：正文本身是合法的（`_check` 当时判否是
因为它带了 ```` ```json ```` 围栏），但结果被标成【执行失败】——见下面第 2 条 bug。

额度：跑完以上约 10~12 次请求后，直连与 CLI 同时 429（`Quota exceeded ... rate-limits`）。
免费档的 rpm 与日配额都远小于"每条 agent 轮次重发全量历史"的用量。

## 这次跑出来的三个真 bug（都已修）

1. **npm 的 `.cmd` shim 不能被 CreateProcess 直接执行**（`app/services/agent/cli/launcher.py`）。
   `shutil.which("codebuddy")` 能过注册表校验，真拉起时 `FileNotFoundError`。
   qwen/claude/codex 这些 npm 装的工具全中，只是以前没在 Windows 上真跑过委派。
   修法是解析 shim 里固定的 `"%dp0%\node_modules\..."` 行，改成 `node + 入口脚本`；
   **不退回 `shell=True`**（那会把模型给的任务文本重新交给 cmd 解析）。
2. **`proc.returncode` 读到 `None`，成功的委派被判失败**（`runner.py`）。
   只等两路读流到 EOF 就去读退出码，asyncio 的子进程回调可能还没跑。
   实测 gemini 已经吐出完整 JSON，结果仍是【执行失败】（`exit=None`）。
   修法：把 `proc.wait()` 和读流一起 `gather`。
3. **未登录文案漏网**（`base.py` 的 AUTH 特征）。
   CodeBuddy 的原文是 `Authentication required. Please use /login command to sign in`，
   一个既有 pattern 都不匹配 → 按普通失败回填，父模型会白重试。已补
   `authentication required` / `please use /login` / `sign in to your account`。

## 各工具的坑

- **Gemini 的 `plan` 档不产出正文**：它把结果写进 `~/.gemini/tmp/<proj>/plans/*.md`，
  stdout 只回一句"已保存"。机械改写必须用 `default`；`plan` 只适合只读分析。
- **Gemini 无头必须信任目录**：不设 `GEMINI_CLI_TRUST_WORKSPACE=true` 会直接退出
  （字面量 `true`，写 `1` 不认）。跨境还要 `HTTPS_PROXY` + `NODE_USE_ENV_PROXY=1`，
  后者由适配器自带。
- **Qoder 的 `--permission-mode` 没有 plan 档**（default/accept_edits/
  bypass_permissions/dont_ask/auto），适配器把 `plan` 映射成 `dont_ask`：
  不弹审批、未预授权一律拒绝。直接透传 `default` 会在无头场景等审批等到超时，
  而 runner 的 stdin 是 DEVNULL。
- **CodeBuddy 的 `--output-format json` 会给 usage / total_cost_usd**，
  是"免费档到底烧了多少"的唯一客观口径，回填时带上。

## 登录后的实测（同日 21:30 补测）

两条 CLI 登录后重跑，走的是生产路径（registry → runner → launcher → CLI → parse_output），
任务是"把一条商品描述改写成一行 JSON"：

| 角色 | 执行体 / 模型 | 结果 | 墙钟 | 自报用量 |
|---|---|---|---|---|
| `cli-grinder` | codebuddy / `deepseek-v4.1-flash` | ✅ 合法 JSON | **9.5s** | 入 45,817 / 出 248，**成本 $0.0000** |
| `cli-grinder-qoder` | qoder / `DeepSeek-Flash` | ✅ 合法 JSON | 29.8s | 未自报（CLI 文本输出无 usage） |
| `cli-grinder-gem` | gemini / `gemini-2.5-flash` | ✅ 合法 JSON | 12.2s | 入 9,400 / 出 36 |

- **`deepseek-v4.1-flash` 是免费的**：CodeBuddy 的 `total_cost_usd` 为 0，不是"看起来免费"。
  它同时说明另一件事——单次 45,817 输入 token 里绝大部分是 CLI 自带的系统提示与工具清单。
- **Qoder 的模型名用显示名**：`qoder --list-models` 返回
  `Auto / Ultimate / Fast / Efficient / Sonus / Cantus / Qwen3.8-Max / Qwen3.8-Flash /
  Kimi-K3.1-Pro / Kimi-K2.8-Preview / GLM-5.3 / GLM-5.3-Flash / DeepSeek-V4-Pro /
  DeepSeek-Flash / MiniMax-M3.1-Flash`，外加用户自建的两条 `(qoder-custom-…)`。
  配置里写 `DeepSeek-Flash`，不是 `deepseek-v4.1-flash`。
- **CodeBuddy 的 json 输出是事件数组**（`message / reasoning / result`），
  前几条 message 事件里带着**完整请求体**（含项目 AGENTS.md）。按单个对象解析会失败
  并回落到裸文本，等于把整份上下文灌回父模型——适配器现在只取最后那条 `type=result`。

## 思考强度与上下文窗口

两条 CLI 都支持，但**默认都不是最大**，要显式传：

| 配置字段 | codebuddy | qoder |
|---|---|---|
| `effort` | `--effort`（minimal/low/medium/high/xhigh/**max**） | `--reasoning-effort`（实测接受 `max`） |
| `context_window` | `--autocompact`（自动压缩阈值，默认跟随模型窗口） | `--context-window`（**不填按 128K 算**） |
| 不填时 | 交给工具默认 | 交给工具默认 |

满档复测（同一任务、同一配置，只改这两个字段）：

| 角色 | 档位 | 墙钟 | 产出 |
|---|---|---|---|
| `cli-grinder`（codebuddy） | max + 1M | **8.7s** | 合法 JSON，$0.0000 |
| `cli-grinder-qoder` | max + 1M | **56.9s** | 合法 JSON（tag 字段跑偏成"316不锈钢"） |
| `cli-grinder-qoder`（对照） | 默认档 | 29.8s | — |

**满档思考的代价是墙钟翻倍**（qoder 29.8s → 56.9s），而且在免费渠道上相当于更快烧额度。

两个必须记住的语义：

1. `context_window` 是"告诉 CLI 按多大窗口管理"，**不会把模型窗口变大**。DeepSeek-Flash / Qwen3.8-Flash 这类免费档本身是百 K 级，写 1M 只会让它误判边界。
2. **执行体拿不到你的会话历史**。`delegate_cli` 传的是一段 task 文本，你平时说的"用满 1M"是客户端侧的累积历史，搬不进 `qoder -p "…"`。要长上下文 + 高思考，走 `/v1`（部署的 `reasoning_effort` + 1M 窗口的模型），不要走执行体。

## 控制台：@ / 直接指定执行体（2026-10-25 晚）

原来只有一条路：让父模型自己决定派活——但模型不一定听话，于是得在提示词里
反复强调「必须用 delegate_cli」，很啰嗦。现在控制台输入框里打 `@` 或 `/`
会弹出执行体清单，选中即**直跑**，不经父模型。

- 选中后出现覆盖栏：模型下拉（`free_models` 里的标「（免费）」）、
  思考档位、上下文窗口——只在 codebuddy / qoder 上出现（gemini 没这俩旋钮）。
- 提交走 `POST /zkadmin/agent/executors`，建一个 `model=cli:<tool>` 的会话；
  不花父模型 token，结果作为一条 assistant 消息落库，**刷新页面还在**，
  左侧会话列表里标题带 `[角色]` 前缀。
- 数据源 `GET /zkadmin/agent/executors`，读的是 `cli_tools.yaml` 的
  `models` / `free_models`；后者只是面板标签，真计费以工具自报为准。
- **改 Python 代码要重启网关**（`python scripts/launch_hidden.py gateway`）；
  只改 `cli_tools.yaml` 不用——每次新任务都会重读花名册。
- 取消：执行体直跑的会话点「停止」只把状态记成 cancelled，**子进程不会被 kill**
  （`run_delegation` 目前没有中途取消的句柄），额度已经烧掉。

### 同一会话里换执行体（22:20 补）

第一版选中一个执行体就独占整条输入，且每次都新建会话——这不对：一个任务流程里
「先让 qoder 读代码、再让 codebuddy 写文档」是常态。现在：

- 已有会话（且不在执行中）里再提交带执行体的任务，走
  `POST /zkadmin/agent/sessions/{id}/messages` + `executor_role`，
  **追加到同一条 transcript**，每条任务各自带 `⚡ 派给 <角色> · <模型>`。
- 没有会话时才 `POST /executors` 新建，标题带 `[角色]`。
- 左侧列表的 `model` 列显示第一条的 `cli:<tool>`（混合会话就是创建时那条）。

### 一条消息点名多个 CLI（22:50 改，第一版的两个毛病）

第一版只在**行首**认 `@`/`/`，正文里出现就弹不出来，也没法「先让 A 查、再让 B 审」。
现在：

- `@` **任意位置**都能触发清单（`/` 仍只认行首，避免和 `a/b` 路径打架）；
  选中后把 `@角色 ` 插进正文，接着写任务。
- 提交时按 `@角色` 切段，**按顺序串行**执行：
  `用 @cli-grinder 查阅xx，再用 @cli-grinder-qoder 审查xx` → 两段，各自落一条消息。
  第一段失败即停，后面的段不再烧额度。
- 分段的分隔符包含中文标点（`，。；、：`）——`…查完，@cli-grinder-qoder 审` 不用补空格。
- 段首尾的标点和「用/然后/再/并/和」这类连接词会被剥掉（可连剥多次）；
  第一个 `@` 之前的文字并进第一段，如果它只是「用」这种填充词就丢掉。
- **每段可以单独设置模型 / 思考 / 上下文**：输入框上方是分段设置面板，默认展开、
  可收起。改文本时同一位置同角色保留选择，换角色则回落默认；默认值来自
  `cli_tools.yaml`（本机 `max` + `1M`）。
- 接口：`POST /zkadmin/agent/delegations`，`items` 最多 10 段，
  每段可带 `model` / `effort` / `context_window`；带 `session_id` 就追加到那条会话。

### 模型清单：优先用 CLI 自己的口径

`GET /zkadmin/agent/executors/{role}/models` 会真的去问 CLI：

| 执行体 | 来源 | 命令 |
|---|---|---|
| qoder | 账号可用模型（含活动模型） | `qoder --list-models` |
| codebuddy | CLI 认的模型清单 | `codebuddy --help` 里的 `Currently supported: (...)` |
| gemini | 无来源，回落配置 | — |

结果缓存 5 分钟；面板选中执行体时先显示配置里的清单，真实清单回来再替换。
**免费标记仍然只能手工维护**（`free_models`）——CLI 只报名字，不报活动价；
要客观判断只能跑一次看 `total_cost_usd`，那要 4.6 万 token，不值得每次探测。
