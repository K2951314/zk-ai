# 6.8 Flash vs DeepSeek V4.1 Flash：能力差异与适用场景

日期 2026-11-05。两轮评测 + 专项稳定性测试，全部直连 `token.sensenova.cn`。
**第一轮结论已作废**（题库太简单，双方都满分），本文件以第二轮为准。

---

## 一句话

**6.8 Flash 是"长程干活的"，DeepSeek Flash 是"快而稳的"。**
综合通过率接近（8/9 vs 8/9），但**失败模式完全不同**——这才是选型依据：

- 6.8 Flash 输在哪：**生成式产物的完成度**（SVG 动画 0/3）
- DeepSeek Flash 输在哪：**带工具的收尾**（chain_s3 两次都漏；还有一次把工具结果原样吐回来）
- 两者都有的问题：**思考 token 极贵**（占输出 42% / 85%）

---

## 一、第二轮成绩（有区分度的题）

| 任务 | 考什么 | 6.8 Flash | DeepSeek Flash |
|---|---|---|---|
| chart | 读柱状图 5 项事实 | ✅ 4.4s / 204 tok | ✅ 8.0s / 1089 tok |
| order_pdf | 读订单截图 + 算总额 | ✅ 4.9s / 236 tok | ✅ 20.9s / 2079 tok |
| chain_s1 | 工具链第 1 步 | ✅ 2.5s | ✅ 1.1s |

| chain_s3 | 工具链收尾（完整转述 4 张单） | ✅ 5.4s | ❌ 两次都只回了裸 tool_calls |
| logic | 四人四刀约束求解 | ✅ 18.5s / 1546 | ✅ 41.6s / 5164 |

## 二、能力差异（按强弱排序）

### ① 生成式产物：DeepSeek 明显更强，而且更**稳**

这是唯一一处**双方差距大到能当决策依据**的能力。同一句提示词
（"用 SVG 画一只骑自行车的鹈鹕，做成 2D 动画"）连跑 3 次：

| | 第 1 次 | 第 2 次 | 第 3 次 | 通过率 |
|---|---|---|---|---|
| **6.8 Flash** | 无动画（169 元素） | 无动画（164 元素） | 无动画（111 元素） | **0/3** |
| **DeepSeek Flash** | 14 个 `<animate>` | 9 个 | 10 个 | **3/3** |

6.8 Flash 还会出一类**更隐蔽的错**：写出 `style="animation-delay:0s"` 却**没有任何
`@keyframes` 或 `animation-name`**——语法上像动画，实际一个像素都不动。

渲染后核对：
- DeepSeek 版本：喙 + 橙色喉囊、翅膀握车把、脚踩踏板、辐条车轮，动画在动
  （帧间差 2.6~3.0 万像素）。
- 6.8 Flash 的成功版本（bench2 里偶然过的 1 次）画得**也很好**——说明它会画，
  只是**不稳定**：同一提示词 3 次里 1 次能出动画。

**判断**：需要一次成型地产出前端代码/SVG/图表配置 → 选 DeepSeek。
它的代价是思考 token 多（见第四节）。

### ② 长程工具链：6.8 Flash 更会"收尾"

`chain_s3` 是三轮工具调用的最后一步：模型拿到 4 张订单，要转述成给客户看的答案。

- **6.8 Flash**：5.4s，4 张订单号 + 全部交期，完整。
- **DeepSeek Flash**：两次都**直接把 tool_calls 原样吐回来**，一个字的自然语言都没有
  （一次甚至没调 `get_order` 就结束了）。

这正是"智能体"和"会调函数的聊天模型"的区别：**知道什么时候该停下来把结果讲给人听**。
6.8 Flash 的定位是"多模态智能体"（官方文案：「长链路自主执行」「多工具协同」），
这一项与定位一致。

### ③ 视觉：两者都能用，但成本差 7 倍

读图能力我一开始被目录骗了——商汤 `/v1/models` 报 `deepseek-flash` 是
`input_modalities: ["text"]`，**实测能读图，而且很准**。

干净的三题（柱数 / 最高月 / 比较）两个模型**全对 3/3**。差别在效率：

| | 视觉两题合计输出 token | 耗时 |
|---|---|---|
| 6.8 Flash | **440** | 9.4s |
| DeepSeek Flash | **3168** | 28.8s |

6.8 Flash 读图只花 204~236 个 token，DeepSeek 要 1089~2079。**它读图几乎不"想"**。
批量做 OCR / 报表/ 截图理解，6.8 Flash 的积分消耗是 DeepSeek 的 1/7。

### ④ 纯文本推理与代码：打平

约束求解（logic）和代码修复（code）两边都过。DeepSeek 更慢更贵（logic 5164 vs 1546 tok），
但没有质量差距。**这一块不值得为谁多花钱。**

---

## 三、成本的真相：思考 token

这是最容易被"免费"误导的一点。积分按 token 扣，而两个模型的思考占比差一倍：

| | 思考 / 输出总量 | 说明 |
|---|---|---|
| 6.8 Flash | **42%** | 读图时思考只占 8~17%；推理题 92% |
| DeepSeek Flash | **85%** | 读图 96~98%、推理 100% |

**同一个任务，DeepSeek 的真实积分消耗是 6.8 Flash 的 3~7 倍**（输出 token 总量）。
6.8 Flash 的"省"不是因为它便宜，是因为它**想得少**。

⚠ 但 6.8 Flash 有个陷阱：**思考与正文共享 `max_tokens`**。给 8192 时它做 logic/code
会把配额全用在思考上（`finish=length`、`content` 为空）——**那是预算问题，不是能力问题**。
给 32768 后立刻全对。部署里 `max_output_tokens: 65536` 是安全的。

## 四、适用场景（直接抄这个表）

| 场景 | 选谁 | 理由 |
|---|---|---|
| 读图表 / 截图 / 订单 / 报表 | **6.8 Flash** | 准，且 token 只要 1/7 |
| 批量 OCR、批量看图 | **6.8 Flash** | 同上，积分消耗差一个数量级 |
| 长链路 agent（多轮工具 + 要收尾） | **6.8 Flash** | 会停、会说人话；DeepSeek 会漏最后一步 |
| 一次成型生成前端 / SVG / 图表配置 | **DeepSeek Flash** | 3/3 vs 0/3，稳定性差一个档 |
| 短平快的机械活（JSON 抽取、改写） | **DeepSeek Flash** | 2.7s vs 25s（第一轮实测） |
| 纯文本推理 / 代码 | 任意 | 打平，DeepSeek 更慢更贵 |
| 650k 超长上下文 | **DeepSeek Flash** | 7.4s vs 181s（第一轮实测） |

**一句话记法**：**看东西、跑流程 → 6.8 Flash；写东西、求快 → DeepSeek Flash。**

---

## 五、当前配置决策（保持不变）

`sensenova-6.8-flash` 已在 `config/models.yaml`，**不进任何别名链**，点名使用。

第二轮数据支持这个决定：两者综合分打平，但**延迟差 5 倍**（中位 5.4s vs 13.4s），
把它放链首会让所有请求变慢；放链尾又基本轮不到。它的正确用法是
「这个任务要读图 / 要跑工具链」时显式点名。
